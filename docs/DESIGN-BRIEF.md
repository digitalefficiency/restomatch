# 🎨 בריף עיצוב — restomatch | עיצוב מחדש של ה-UX/UI מקצה לקצה

> בריף ל-Claude Design (או כל כלי עיצוב מבוסס AI). מבנה: CO-STAR. כל טקסט ה-UI שייווצר — בעברית RTL.

אתה/את מעצב/ת מוצר ו-UI בכיר/ה. המשימה: לעצב מחדש את כל חוויית המשתמש של restomatch בשפה עיצובית נועזת, טרייה ומובחנת — לא טמפלייט אדמין גנרי, אלא זהות חזותית שמרגישה כמו "חדר בקרה לכסף".

## C — הקשר: מה המערכת ומה הייעוד

restomatch היא מערכת SaaS למניעת דליפות כספיות (loss-prevention) למסעדות בישראל.

**הבעיה:** מסעדות מאבדות אחוזים מהרווח בגלל פערים שקטים בין מה שהזמינו, מה שקיבלו בפועל, ומה שחויבו בחשבונית — מחירים שעלו, כמויות חסרות, פריטים שלא הוזמנו, חשבוניות כפולות, טעויות מע"מ.

**הפתרון:** המערכת משווה אוטומטית שלושה מסמכים — הזמנת רכש (PO) ↔ קבלת סחורה (GR) ↔ חשבונית — מזהה 12 סוגי פערים, מדרגת חומרה (מידע / אזהרה / חוסם), מנתבת כל פער לאדם הנכון לאישור, ומכמתת בשקלים כמה כסף בורח וכמה נחסך.

**החזון:** להפוך כאוס של ניירת ספקים לחדר בקרה אחד שבו בעל המסעדה רואה בשנייה איפה דולף כסף — ולוחץ כפתור כדי לעצור.

**המצב היום:** המערכת עובדת אבל ה-UI פונקציונלי ו"שירותי" — לא משדר את העוצמה והאמון של מוצר פינטק פרימיום.

## O — מטרת העיצוב

לייצר שפת עיצוב חדשה ומלאה (design system) + עיצוב כל מסכי המערכת, עבור 4 סוגי משתמשים. זהות חזותית ייחודית, לא גנרית.

## S — סגנון

- **נועז וטרי:** הצע פלטת צבעים ייחודית (לא כחול-SaaS דיפולטי), טיפוגרפיה אקספרסיבית, ומוטיב חזותי חתימה — למשל מטפורת "זרימת כסף / דליפה" שחוזרת בגרפים ובמעברים. יש לך חופש לחדש בצבע, בטיפוגרפיה ובאווירה.
- **שפה ויזואלית:** "command center" פינטק — צפוף-נתונים אך רגוע, חד ובטוח. דאטה-ויזואליזציה במרכז (heatmaps, מגמות, sparklines, KPI חיים).
- **פרימיום ואמין:** המוצר נוגע בכסף — כל פיקסל צריך לשדר דיוק ואמון. עומק עדין (shadows / glass), לא שטוח-משעמם ולא עמוס מדי.
- **עברית-first:** בחר טיפוגרפיה עברית חזקה (display + text), לא רק ברירת מחדל. פריסת RTL נכונה לחלוטין (כיווניות, מראה אייקונים, יישור).
- **השראה (mood references — להשראה, לא להעתקה):** החדות התפעולית של **Linear**, האמון הפיננסי של **Ramp / Mercury**, והבהירות התכליתית של **Monday** — אבל עם זהות עברית-first מובחנת ומקורית משלנו, לא חיקוי.

## T — טון

בטוח, חד, מרגיע — "אנחנו שולטים בזה בשבילך". טקסט ה-UI בעברית: ישיר, אנושי, בלי ז'רגון; מספרים גדולים וברורים; שפת פעולה ("אשר", "עצור דליפה", "הצג בתור").

## A — קהל (personas)

1. **בעל/ת המסעדה** — עסוק/ה, רוצה תמונת-על בשנייה: כמה כסף בסיכון, כמה נחסך, מה דורש החלטה. מסכים: לוח בקרה (KPIs + heatmap דליפות + scorecards ספקים + פיד פעילות), בלש דליפות, דירוג ספקים. Web + מובייל.
2. **מנהל/ת** — מהירות: תור אישורים של חריגות, החלטות מהירות (אשר / דחה עם סיבה). Web + מובייל.
3. **מקבל/ת סחורה** — בשטח, ידיים עסוקות, מובייל-first: רואה הזמנות היום → פותח קבלה → מסמן כמות/מצב שורה-שורה → מצלם חשבונית. מסכים גדולים, מגע נדיב, מהיר.
4. **מנהל/ת חשבונות / רו"ח** — דיוק: ייצוא לתקופה (CSV + "קובץ אחיד" לרשויות המס).

**הקשר:** מסעדות בישראל — עברית, ש"ח (₪), מע"מ, פורמט מס ישראלי, שעות אספקה מקומיות.

## R — מה לייצר

1. **שפת עיצוב (foundations):** פלטה (כולל סמנטיקה חיובי / אזהרה / חוסם / ניטרלי), טיפוגרפיה (סקאלה עברית), מרווחים, רדיוסים, צללים/עומק, אייקונוגרפיה, מוטיב חתימה, עקרונות מושן.
2. **ספריית קומפוננטות:** כרטיס, כפתור (וריאנטים + מצבים), badge חומרה, KPI card, טבלה, כרטיס תור-אישור, שדות טופס, מצבי ריק/טעינה/שגיאה, ניווט.
3. **מסכי מפתח לכל פרסונה** (desktop + mobile היכן שרלוונטי): לוח בעלים, בלש דליפות (heatmap product×supplier), דירוג ספקים, תור אישורים, flow מקבל-סחורה (מובייל), ייצוא רו"ח, מציג חשבונית סרוקה + השוואה ל-PO, login + onboarding.
4. **ויזואליזציות דאטה:** heatmap סטיית מחיר (מוצר×ספק), מגמות מחיר (sparkline), KPI עם דלתא/מגמה, פיד פעילות חי.

## אילוצים מחייבים

- RTL מלא + כל טקסט ה-UI בעברית.
- נגישות WCAG AA: ניגודיות, focus rings, ARIA, ניווט מקלדת.
- רספונסיביות: בעלים/מנהל ב-web+מובייל; מקבל-סחורה מובייל-first.
- מצבי ריק/טעינה/שגיאה לכל מסך.
- פורמט מטבע ₪ ותאריך ישראלי.

## פורמט הפלט הרצוי

התחל בהצגת שפת העיצוב (מוד-בורד: פלטה + טיפוגרפיה + מוטיב חתימה + 2-3 קומפוננטות מפתח) לאישור — ואז עבור מסך-מסך. לכל מסך: פריסה, היררכיה ויזואלית, הקומפוננטות בשימוש, והמצבים (ריק/טעינה/שגיאה). נמק כל החלטה עיצובית מרכזית.
