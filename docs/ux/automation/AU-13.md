# AU-13 · Prices that went up, in ₪ per month: one morning mail instead of one per alert, plus contracts ending and dishes crossing their target

**One line:** the 07:00 price sweep sends each owner and manager **one** "מחירים שעלו" mail: new rises ranked by ≈₪/month (W2-12's estimate), contract prices ending within 14 days, and a new supplier price list's rises. The chef gets only the dishes whose food cost crossed the target this month (₪ on recipes is allowed). None of it is leak ₪, and nothing writes `price_history` (AD11).

## 5. Acceptance
1. One mail per owner/manager per Israel day, dedupe `au:A18:<rid>:<userId>:<ilDate>`; `notified_at` set only after every recipient is queued, and only when a mail was newly queued (a same-day rerun leaves a new alert for tomorrow).
2. Contracts with `valid_to` ∈ [today, today+14] (Israel-day strings), no renewal, grouped by supplier; once via audit `prices.contract_expiry_notified`.
3. Dishes: chef mail holds only the dish section; owner/manager get it as a section; once per dish per month (`prices.dish_crossing_notified`).
4. ₪ through one formatter; LIGHT template from `ui-tokens`; no "דליפה" / "פער" / "1.5%"; no hours estimate.
5. Price-list diff: rises only, mean %, top 5, no ₪/month; once per import (`prices.list_diff_notified`); no `price_history` / `price_baselines` row written.
6. Receiver and bookkeeper get zero rows; every reader restaurant-scoped; a failing tenant never stops the loop.
7. Off switches: `priceAlerts` off → nothing; `priceCreepDigest` off → alerts in-app only (per-alert mails do not come back); `contractExpiry` / `priceListDiff` off → section omitted; `dishPriceAlert` off → no chef mail.
8. KPI hook: outbox prefix `au:A18:`, payload `{ kpi: 'A18', alertIds, creepMonthlyAgorot }`; the three audit actions above.
