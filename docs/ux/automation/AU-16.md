# AU-16 · Earned autonomy: the owner lets a trusted supplier's small gaps decide themselves
**One line:** after 10 clean invoices from a supplier, the owner is offered "אשר אוטומטית פערים קטנים של <ספק> עד ₪300". Before granting, the owner sees what the rule **would have done** in the last 90 days; after granting, every auto-decision is listed, reversible, and still claimed from the supplier (never waived).
- **Impact (assumption):** 12–24 small-gap invoices/month at the ICP restaurant × 1–2 min of owner/manager attention = 0.05–0.2 h/week ≈ **₪22–90/month time-₪** (₪30–130 at the owner's ₪150/h; catalogue A21). Money-₪: none new; the claim ₪ is identical to a human "דרוש". Risk budget: ≤₪300 per auto-decided invoice. Never summed with leak ₪.
- **Today:** every finding is decided one card at a time (`approvals.ts:377-420`; int-03 §5: no batch, no learned rule); the only auto-approve is `minor-info` on small runs (`approvals/engine.ts:172-178`). No supplier-level rule exists.
**Owner agent:** web-feature-engineer (leak-economist signs the copy and the "would have" ₪; tenant-security-warden reviews grant/revoke/reverse; icp-keeper confirms it stays an owner tool, not an AP robot). **Device:** both (grant on desktop; the reversal tap on phone). **Effort:** L (3 PRs: a = eligibility + shadow mode; b = grants + list after H-13; c = reverse + approvals badge after H-12). **humanPR:** yes, via H-12 (the rule in `approvals/engine.ts`) and H-13 (`autonomy_grants`); this package edits neither.

## 5. Acceptance criteria
1. **`autonomy.eligible`** (owner, manager and bookkeeper read; query). Per active supplier: `{supplierId, cleanCount, windowDays: 180, lastDirtyAt | null, gapRate90d, smallGapInvoices90d, smallGapIls90d, eligible: cleanCount >= AUTONOMY_MIN_CLEAN (10) && !newSupplier && !bankChangedRecently}`. A clean invoice = latest match run in `matched|approved|paid`, not consolidated (T4), no finding with severity `block`, no DUPLICATE_INVOICE, no UNORDERED_ARRIVAL/ITEM, and leak-filtered ₪ (NEVER_CLAIMABLE excluded) = 0. `cleanCount` counts the last consecutive clean invoices. Consolidated invoices are skipped, not counted as dirty.
2. **`autonomy.simulate`** (owner; query) `{supplierId, maxAgorot ≤ 30000, types ⊆ ['PRICE_HIGHER','QTY_SHORT','QTY_OVER']}` → for the last 90 days: `{invoicesAutoDecided, findingsAutoDecided, ilsClaimedAutomatically (agorot), invoicesStillToOwner, reasons: {block, duplicate, overCap, overPct, typeNotGranted}}`. It replays H-12's predicate over persisted findings by importing `supplierAutonomyApplies(ctx, t)` (+ `AUTONOMY_TYPES`, `AUTONOMY_MAX_ILS`), which H-12 §5.4 exports from `approvals/engine.ts` and the `@restomatch/api` root; and, as a cross-check, it runs `evaluateApproval(buildRules(t))` on the constructed context and counts `ruleId === 'supplier-autonomy'` (the two must agree; a test pins it). It never writes. Before H-12 merges, it uses a local copy of H-12 §5.4 behind one `autonomyPredicate()` import (one-line swap).
3. **`autonomy.grant`** (owner only; mutation; after H-13). Input `{supplierId, maxAgorot, types, clientMutationId}`. Server checks:
   - `eligible` true now
   - `maxAgorot` ≤ min(30000, tenant `cumulativeLargeAmount`×100)
   - no active grant (CONFLICT "כבר קיים כלל לספק הזה"). Writes the row with `basis` = the eligibility + simulation snapshot shown in the dialog, and one audit row `autonomy.granted` `{grantId, supplierId, maxAgorot, types, automationId:'A21'}`. Replay → same result, no second row. Non-owner → FORBIDDEN.
4. **`autonomy.revoke`** (owner; mutation) `{grantId, clientMutationId}` → `revoked_at`, `revoke_reason 'owner'`, audit `autonomy.revoked`. Future runs only (H-12 §5.7); the dialog says "החלטות שכבר התקבלו נשארות. אפשר לבטל כל אחת מהרשימה."
5. **`autonomy.reverse`** (owner, manager; mutation; after H-12) `{discrepancyId, clientMutationId}`:
   - only for a finding with `rule_id='supplier-autonomy'` and `resolution_status='accepted'`
   - moves it to `open` (G-05 guarded transition; CONFLICT if it moved meanwhile) routed to the role H-12's rules give without autonomy
   - if its claim already has `letter_sent` or later, refuse with "הדרישה כבר נשלחה לספק · טפלו בה בדף הזיכויים". Audit `autonomy.reversed` `{grantId, discrepancyId, automationId:'A21'}`. Effect: H-12's `reversalSinceGrant` pauses the grant
   - the list shows "הכלל הושהה" with "הפעילו מחדש" (a new grant, owner).
6. **`autonomy.list`** (owner, manager, bookkeeper read): grants with `{supplier, maxAgorot, types, grantedBy, grantedAt, state: active|paused|revoked, autoDecided30d, ilsClaimed30d, reversals30d}` and the last 20 auto-decided findings (invoice, type, ₪, date, "בטלו").
7. **Page `/dashboard/settings/automations/autonomy`** (owner edits; manager/bookkeeper read-only; receiver/chef get the forbidden page, server-enforced).
   - Title "החלטות אוטומטיות לפי ספק". Intro: "פערים קטנים אצל ספק שהוכיח את עצמו נרשמים לדרישת זיכוי בלי לחכות לכם. חסימות, כפילויות, ספק חדש ושינוי פרטי בנק תמיד מגיעים אליכם."
   - Offer card (eligible, no grant): "<ספק>: 10 חשבוניות אחרונות ללא פערים" · "אילו הכלל היה פעיל ב-90 הימים האחרונים: 7 חשבוניות היו נרשמות אוטומטית, ₪412.50 היו נדרשים מהספק, 2 היו עוברות אליכם" · button "הגדירו כלל" (T3 calm tone, not T2).
   - Grant dialog: ₪ cap stepper (default ₪300, max ₪300 or the tenant's large threshold), type checkboxes ("מחיר גבוה מהמוסכם", "חוסר בכמות", "כמות עודפת"), the shadow numbers, the sentence "כל פער שיוחלט אוטומטית נרשם כדרישת זיכוי, לא כוויתור", ConfirmDialog.
   - Active grant row: the ₪ cap via `<Money>`, counts, "ביטול כלל"; a paused grant shows the reason.
8. **Approvals badge.** A finding decided by the rule shows `AutoDecidedBadge` "הוחלט אוטומטית · כלל ספק" (T3) with "בטלו" (owner/manager) in the approvals history and on the invoice's findings; it never appears in "מחכה לך" counts.
9. **Copy and ₪.** ₪ via `formatIls()`/`<Money>` in UI, `moneyText` in any server text; never "אושר לתשלום", never "ויתור", never "1.5%"; he/en parity; RTL; numbers right-aligned.
10. **Off switch.** Option `supplierAutonomy` (AU-01 registry, default false) gates every mutation and the offer card;
    - the page shows the read-only shadow even when off. `FEATURES_OFF` has no key for it
    - the admin kill-switch is revoking grants (admin action listed in AU-01's panel) or H-12's loader returning null.
11. **Roles (server).** grant/revoke = owner; reverse = owner + manager; reads = owner, manager, bookkeeper; receiver and chef FORBIDDEN on every `autonomy.*`.

Where the docs conflict: the spec says "earned-autonomy UI (settings + approvals card)". The approvals page is W2-04's then W3-01's, so the card is a badge component in a new folder with one requested mount line, not a folder under `dash/approvals/**`.
