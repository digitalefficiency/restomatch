# AU-19 · Payment file and bank-evidenced recovery: pay only the undisputed ₪, prove the ₪ came back
**One line:** an approved pay run becomes one Masav (מס״ב) credit file of the **undisputed** amounts plus a remittance note per supplier that names what was withheld; a human uploads and signs it at the bank. Later, the bank statement the owner exports is matched to claims and payments, so "הוחזר" is backed by a bank line instead of a click.
- **Impact (assumption):** 12–20 supplier transfers a month typed into the bank one by one fall to one file: owner/bookkeeper 0.06–0.2 h/week ≈ **₪25–80/month time-₪**. Money-₪: none new (the recovered ₪ is already counted in A12); the gain is that AU-07's recovery rate becomes **evidenced**, and a disputed ₪ can no longer slip into a transfer typed from an invoice total. Never summed.
- **Today:** the pay run is read-only and ends in a client CSV (`apps/web/app/dashboard/approvals/pay-run/export-button.tsx:8-14`); no code marks an invoice paid outside the demo seed (`routers/payRun.ts:25-26`; bug 8, catalogue §D); `recovered` is a manual 3-click dialog with no evidence (int-04 §5 step 4); no Masav output exists anywhere.
**Owner agent:** web-feature-engineer (tenant-security-warden **mandatory**: bank numbers are decrypted for the file; leak-economist signs "undisputed" and the remittance; matching-engine-guardian confirms no ₪ definition moves). **Device:** desktop (file + statement), phone for the owner's confirm. **Effort:** L (3 PRs: a = Masav file + remittance bundle; b = mark-paid-from-file; c = statement match → recovered proposals). **humanPR:** no (no schema: `export_runs`, bank tables and `paid_*` are H-03's; Masav settings live in `restaurants.settings` jsonb, H-13 §5.4). The file layout constant is human-confirmed before the option can be enabled.

## 5. Acceptance criteria
1. **`payments.masavPreview`** (owner, bookkeeper; query) `{invoiceIds}` → per supplier `{supplierId, bank: {bankCode, branchCode, last4} | null, invoices[{invoiceId, number, totalAgorot, heldAgorot, offsetAgorot, payAgorot}], payAgorot, excluded[{invoiceId, reason}]}` where `payAgorot = total − deductions (G-03) − held`; exclusion reasons: `preflight_hold` (AU-14 hard flag, incl. unconfirmed bank change), `on_hold` (W2-03 hold: undecided leak, duplicate copy, missing allocation number, `note_billed_twice`), `no_bank_details`, `bank_unverified`, `already_paid`, `zero_or_negative`. Integer agorot only. Receiver/chef/manager FORBIDDEN.
2. **Layout gate.** `masavLayout.ts` holds the credit-file layout (record types, field widths, padding, encoding, line ending) as a named constant with `MASAV_LAYOUT_SOURCE` (document title + version) and `MASAV_LAYOUT_CONFIRMED: boolean`. It stays `false` until a human (the owner's bank or the bookkeeper) confirms the layout against Masav's published spec and one test upload;
   - the PR body asks for it. While false, the build procedure returns PRECONDITION_FAILED `MASAV_LAYOUT_UNCONFIRMED` and the UI hides the button. Don't guess beyond the constant
   - a golden-file test pins whatever the human confirms.
3. **`payments.buildMasavFile`** (owner, bookkeeper; mutation) `{invoiceIds, valueDate, clientMutationId}`: re-runs §5.1 server-side (never trusts the client's amounts), calls `assertPreflightClear` (AU-14), requires `restaurants.settings.masav.instituteCode` (owner sets it in `payments.setMasavSettings`, one jsonb merge, audited), decrypts each account number in memory only, returns `{fileName, contentBase64, sha256, totalAgorot, lines}` once. It stores **no file** and writes **no `export_runs` row**: H-03's `export_runs` has no `kind` or `sha256` column (it has `format`, `mode IN ('new_only','all')`, `range_from/range_to`, counts, `total_agorot`; `docs/ux/wave2/H-03.md:105`), a Masav run fits neither mode nor a date range, and `export_run_invoices` rows would mark the invoices "exported to bookkeeping", which AU-12 and W2-14 read. The run's only record is one audit row `payments.masav_built` `{masavRunId (uuid), sha256, invoiceIds, totalAgorot, lines, valueDate, automationId:'A24'}` (H-13 §5.4 records this choice). Replay → same result, no second row. Amounts > 0 only; one line per supplier (sum of its invoices), the invoice numbers in the free-text field.
4. **Remittance bundle.** With the file, `payments.remittanceBundle` returns AU-14's `remittanceText` per supplier in the file (he/en, `wa.me`/`mailto` pre-addressed). Nothing is sent by the server. Undecided holds read "בבדיקה" with no ₪ (AU-14 rule).
5. **Mark paid from the file (PR b).** On the file's page:
   - "העליתי וחתמתי בבנק · סמנו כשולם" (owner, bookkeeper) → W2-03 `markPaid` for exactly the file's invoices with `{paidAt: valueDate, paidAmount: payAgorot/100, paymentMethod: 'bank_transfer', paymentRef: 'masav:<masavRunId>'}` and AU-14's acknowledged soft flags
   - all-or-nothing
   - a stale invoice (paid or changed since the file) → CONFLICT listing it. Never automatic on file generation.
6. **Statement match (PR c).** The browser parses the owner's bank export (CSV; a column-mapping step "תאריך · תיאור · חובה · זכות · אסמכתא", presets per bank saved in `settings.bankStatementMapping`); it sends only normalised lines (`date`, `amountAgorot`, `direction`, `text` ≤140 chars, `refHash`), ≤2,000 lines. `payments.matchStatement` (owner, bookkeeper) returns proposals, writes nothing:
   - **incoming** credit from a supplier (name or ח״פ in `text`, amount = a claim's/credit note's owed amount converted by `vatBasisOf`: `excl` × (1 + supplier/restaurant VAT), `incl`/`vat` as is, ±₪1) → propose `credited → recovered` for those claims (claims still `acknowledged`/`letter_sent` → propose "רשמו חשבונית זיכוי" via W2-10's form, never a status jump);
   - **outgoing** debit equal to a file line or a marked-paid invoice's `paid_amount` (±₪0) → "תשלום אומת בבנק" evidence; when that payment carried `payment_deductions`, the deducted claims show "קוזז בתשלום · אומת" (state per W2-03/G-14; no transition invented here);
   - unmatched lines are dropped and never stored.
7. **`payments.confirmEvidence`** (owner; mutation) `{proposals[{kind, claimIds | invoiceId, refHash, expectedStatus}], clientMutationId}`: for `recovered` runs `transitionClaim` with `expectedStatus` and note `bank:<refHash>`; for payment evidence writes only the audit row. Each writes `recovery.bank_evidence` / `payments.payment_evidence` `{refHash, lineDate, amountAgorot, automationId:'A24'}`. Bookkeeper may confirm payment evidence, not `recovered` (money state: owner, as W2-10's dialog).
8. **Page `/dashboard/payments`.** Tabs "קובץ מס״ב" · "התאמת דף בנק". File tab:
   - selected invoices from the pay run (deep link carries ids), per-supplier rows with `<Money>` pay/held/offset, excluded rows with the reason in words, "צרו קובץ" (disabled with the reason when the layout or settings are missing), then download + remittance list + "סמנו כשולם". Statement tab: upload, mapping, proposals grouped "החזרים מספקים" (T3 gold) and "תשלומים שאומתו" (T4 neutral), "אשרו" per row. Owner and bookkeeper
   - manager read-only
   - receiver/chef forbidden (server).
9. **Safety (server tests).** A held, disputed or bank-changed invoice is never in a file; Σ file = Σ `payAgorot` to the agora; no account number in any log, audit row or response except the one file; no outbound network call; `markPaid` and `recovered` happen only on a confirm mutation.
10. **Off switch.** Option `masavFile` (default false) + `MASAV_LAYOUT_CONFIRMED`; statement matching behind the same option (or its own `bankEvidence` option if the owner wants one without the other). Off → procedures return `{enabled:false}`, the nav item hides.
11. **Copy.** "קובץ מס״ב", "לתשלום", "בבדיקה", "קוזז", "הוחזר · אומת בבנק"; never "שולם" before the human confirms; ₪ via `formatIls()`/`<Money>` in UI and `moneyText` in texts; he/en parity.

Where the docs conflict: A24 says "approved pay run → Masav file"; on train A there is no "approved" pay-run state (only the G-15 pay-approval rule, wave 3). This package builds the file from a **selection** the user makes in the pay run, re-validated server-side; when G-15's `approve_for_payment` lands, the file accepts only approved invoices (one predicate swap).
