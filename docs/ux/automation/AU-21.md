## 5. Acceptance criteria
1. **SKU on synced lines (C1).** `syncOrders` writes `supplier_sku` from the line's own `sku` **when the platform sends one** — never from the platform product id (a MarketMan product id is not the supplier SKU printed on the invoice; using it would fail to pair or mis-pair). The platform line/product id is never used as `supplier_sku`. Once H-04 lands it is stored as `external_line_id`; **until H-04, nothing is written into `notes`** (no `platform_line:` tag): the line key is only the composite key of AC3 (preferred interim, §5.14). Then `decideLink` runs per line: auto-link only on SKU or alias; anything else is a review item, never a silent product.
2. **Never eligible without a key — enforced inside AU-21's paths.** Eligibility in `buildMatchInput` is status-only and `match/**` is G-04's, so AU-21 does not rely on a matching change: `syncOrders` stores a synced PO with any line that has neither SKU nor product as **`draft`** (not in `ELIGIBLE_PO_STATUSES`). The hold is **derived, not tagged**: `keyHold.ts` treats a `source='platform'` PO in `draft` with any unkeyed line as held (no `held_for_keys` note). When the last line is mapped, `keyHold.ts` releases it to the platform's current mapped status from the next sync (subject to AC4). Day-1 QUESTION to G-04 (#188): if its merged diff already carries the same rule, AU-21 keeps the hold anyway (belt and braces) and says so in the PR body. Test: held PO not discovered by `buildMatchInput`; after mapping, discovered. Copy on the PO: "יש שורות בלי קישור למוצר — ההזמנה לא נבדקת מול חשבונית עד שיקושרו".
3. **Upsert, never delete (C2).** Lines are upserted by `lineKey(platformLineId ?? sku ?? normalised description + unit)`. A line that a `gr_lines.po_line_id` points at is never deleted or re-keyed; a platform line that disappears is left in place, not removed (marking it cancelled waits for an H-04 column; no `notes` tag). Interim key until H-04: the same composite AU-20 uses, and nothing else; with H-04, `external_line_id`.
4. **Our status wins after the dock (C3).** `statusPrecedence(ours, theirs)`: once a goods receipt exists, the platform may move nothing; platform `closed`/`cancelled` is **not written into `notes`** (no `platform_status:` tag) and does not move our status. Storing it and showing "סגור ב-MarketMan" waits for an H-04 column. Before any receipt, platform `cancelled` cancels. **Carve-out for the key hold (AC2):** a `held_for_keys` PO stays `draft` whatever the platform says, except platform `cancelled`, which cancels; on release it takes the platform's mapped status through this same table. Table-driven test over every pair, including the held rows.
5. **Unmapped supplier is visible.** A skipped order increments a per-connection counter read by `health.ts`; no `console.warn`-only path remains.
6. **Price list = expected price only (PR b, C4).** `listProducts` produces a diff in W3-10's shape. The owner confirms in "מה ישתנה"; only then is `supplier_catalog_items.list_price` written.
