## 5. Acceptance criteria (the exact proposal)
1. **Routing amount (commit a).** New pure `routingAmount(findings, invoiceTotalInclVat): number`:
   ```ts
   // integer agorot inside, shekels out (2 dp), capped at the invoice total
   Σ round(|Δ|·100) over findings where severity ∈ {warn, block}
     AND type ∉ NEVER_CLAIMABLE_TYPES            // PRICE_LOWER, UNORDERED_ARRIVAL, MISSING_ON_INVOICE
     AND NOT (type = DUPLICATE_INVOICE AND carried decision = rejected)
   → min(sum/100, max(invoiceTotalInclVat, 0))
   ```
   `ApprovalContext.matchRun` gains `routingAmount?: number`. `cumulative-large`, `cumulative-medium` and `discrepancyPct` read `routingAmount ?? totalDiscrepancyAmount` (undefined keeps today's behaviour for any other caller). `persist.ts` passes it; `match_runs.total_discrepancy_amount` keeps storing the engine Σ (unchanged meaning).
2. **Effect pinned by tests:** a run with one MISSING_ON_INVOICE warn Δ ₪400 and one PRICE_HIGHER warn Δ ₪40 on a ₪4,000 invoice: today both → owner `queue_review` (`cumulative-large`); after: PRICE_HIGHER → fallback/medium per amount (₪40 → fallback manager), MISSING_ON_INVOICE → manager (acknowledge path per G-15). A `block` finding still → owner (`severity-block`, priority 80, unchanged). Duplicate → bookkeeper block (100, unchanged).
3. **Autonomy context (commit b).** `ApprovalContext.matchRun` gains:
   ```ts
   autonomy?: { grantId: string; maxIls: number; types: DiscrepancyType[] } | null;
   signals?: { hasBlock: boolean; hasDuplicate: boolean; newSupplier: boolean;
               bankChangedSinceLastPayment: boolean; reversalSinceGrant: boolean };
   ```
   `loadAutonomyContext(db, restaurantId, invoiceId, findings)` (in `approvals/autonomyContext.ts`) returns `null` unless **all** hold: option `supplierAutonomy` on (`automationOption`, AU-01); the invoice has a `supplier_id`; exactly one active grant (`revoked_at IS NULL`) for `(restaurant_id, supplier_id)`; the table exists. Signals: `hasBlock` / `hasDuplicate` from this run's findings; `newSupplier` = fewer than `AUTONOMY_MIN_CLEAN = 10` matched invoices of the supplier or supplier created < 30 days ago; `bankChangedSinceLastPayment` from H-03's change audit after the supplier's latest `paid_at` (**table missing or query error → true**); `reversalSinceGrant` = any finding of this supplier with `rule_id = 'supplier-autonomy'` moved off `accepted` by a person after `granted_at`.
4. **The rule** (priority **65**: below duplicate 100, large-without-PO 95, unordered-significant 90, severity-block 80, cumulative-large 70; above cumulative-medium 60):
   ```ts
   { id: 'supplier-autonomy', priority: 65,
     name: `כלל ספק: החלטה אוטומטית עד ₪${max} (הוענק ע״י הבעלים)`,
     predicate: (ctx) => supplierAutonomyApplies(ctx, t),
     decision: { requiredRole: null, action: 'auto_approve' } }

   // Exported, pure: the one predicate AU-16's shadow mode imports (never re-implemented).
   export function supplierAutonomyApplies(ctx: ApprovalContext, t: ApprovalThresholds): boolean {
     const g = ctx.matchRun.autonomy, s = ctx.matchRun.signals;
     if (!g || !s) return false;
     if (s.hasBlock || s.hasDuplicate || s.newSupplier || s.bankChangedSinceLastPayment || s.reversalSinceGrant) return false;
     if (ctx.discrepancy.severity !== 'warn') return false;
     if (!AUTONOMY_TYPES.includes(ctx.discrepancy.type) || !g.types.includes(ctx.discrepancy.type)) return false;
     const amt = ctx.matchRun.routingAmount ?? ctx.matchRun.totalDiscrepancyAmount;
     return amt <= Math.min(g.maxIls, AUTONOMY_MAX_ILS, t.cumulativeLargeAmount) && discrepancyPct(ctx) <= t.cumulativeLargePct;
   }
   ```
   `supplierAutonomyApplies`, `AUTONOMY_TYPES` and `AUTONOMY_MAX_ILS` are exported from `engine.ts` and added to the `packages/api/src/index.ts:128-131` export block (additive). `engine.ts` is immutable, so this export must ship in H-12 itself; AU-16 cannot add it later.
   `AUTONOMY_TYPES = ['PRICE_HIGHER','QTY_SHORT','QTY_OVER']`; `AUTONOMY_MAX_ILS = 300` (AD7). Never: DUPLICATE_INVOICE, UNORDERED_ARRIVAL, UNORDERED_ITEM, MISSING_ON_INVOICE, PRICE_LOWER, UNIT_MISMATCH, VAT_MISMATCH, TOTAL_MISMATCH, DATE_ANOMALY, any `block`.
5. **What "auto-approve" writes under this rule.** `resolution_status = 'accepted'` (= claim it; G-14 decision `claim` with a system actor), `resolved_at = now()`, `resolved_by = NULL`, `resolution_note = 'auto:supplier-autonomy:<grantId>'`, `rule_id = 'supplier-autonomy'`. It is **never** a waive/reject and never G-14's `tolerate`:
   - the ₪ stays in the leak and becomes a claim through `syncClaims`
   - the letter still needs a human tap (W2-10, AU-17). One `audit_log` row per auto-decided finding, actor NULL: `action 'approvals.auto_decided'`, `after {ruleId, grantId, routingAmount, invoiceId, automationId: 'A21'}`. No notification for it
   - the activity line reads "הוחלט אוטומטית לפי כלל ספק · ₪X לדרישה" (₪ via `moneyText`).
6. **Re-match.** `decisionStillApplies` gains: a prior with `resolved_by IS NULL` and a `resolution_note` starting `auto:supplier-autonomy:` applies only when the new decision is again `supplier-autonomy` **with the same grantId**; otherwise the finding starts fresh (open, routed, notified). Re-match refusals for claims with money history (`service.ts:907-946`) are unchanged.
7. **Revocation and reversal are future-only.** Revoking a grant changes no existing row. A person reopening/rejecting an autonomy-decided finding sets `reversalSinceGrant` for that supplier, so the rule stops at once; AU-16 shows "הכלל הושהה: החלטה אוטומטית בוטלה ע״י <name>" and asks the owner to re-grant.
8. **Routing diff, signed.** `scripts/routing-diff.ts` runs both rule sets over every open finding of the lab tenant and prints `{invoice, type, Δ, before: role/action/rule, after: role/action/rule}`. The PR attaches it. Expected:
   - hero leak ₪759.54 and "₪463.54 to claim" unchanged
   - "₪296.00 awaiting decision" may move between owner and manager rows (both numbers before/after stated)
   - leak-economist and the owner sign.
9. **Per-tenant thresholds still win:** a tenant with `cumulativeLargeAmount: 200` caps autonomy at ₪200 (the `Math.min` in item 4); tests cover it.

Where the docs conflict: the spec lists "(3) info-only runs auto-approve before the total rules" as H-12 content. G-15 item 3 (GAP-PACKAGES 222-232, human, Dec) already routes info/non-leak rows to an acknowledge path before the cumulative rules, and G-14 gives that auto-approval the `tolerate` decision.
