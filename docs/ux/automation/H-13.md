# H-13 · Schema batch C: the three facts automation must store, and nothing more
**One line:** the owner's autonomy grants, the supplier replies to a claim, and the supplier's consent and reconciliation contact get real, tenant-isolated homes; everything else the automation track needs stays in existing jsonb or `audit_log`, so the batch is two tables and four nullable columns.
- **Why it matters (assumption, ICP restaurant):** without `autonomy_grants` the AD7 rule (H-12) cannot exist; without `claim_replies` a supplier's "we'll credit you ₪180" in WhatsApp or e-mail is thrown away at ingest (only the subject survives, `schema.ts:1387`; text-only messages end `empty`, `ingest/pipeline.ts:390-425`); without supplier opt-in, a server-sent WhatsApp template to a supplier (AU-17) breaks Meta policy. No ₪ figure changes: these are enabling rows.
- **Today:** the closest existing table, `approval_rules` (`schema.ts:1248-1260`, in the RLS list `rls/0002_core_tenant_rls.sql:54`), is read by no code path and has no supplier FK, no grantor and no revocation stamp.

## 4. What to fix and build
- **Findings (train A):**
  - no store for an owner's per-supplier grant (AD7); `approval_rules` is a generic jsonlogic table with no supplier FK, grantor, revocation or cap, and nothing reads it;
  - supplier replies are lost: `ingest_messages` keeps `subject` but no body (`schema.ts:1371-1396`); a text-only WhatsApp from a supplier is either order capture or `empty` (`pipeline.ts:390-425`);
  - suppliers have one contact pair (`schema.ts:432-433`) and no consent stamp; Meta requires recipient opt-in for business-initiated templates (ext-02 §4);
  - AU-18's missing-documents ask often goes to the supplier's bookkeeping desk, not the order line (int-00 gap 9; ICP: "dozens of invoices never reached the system").
- **Catalogue:** A21 (grants), A22 (replies, opt-in), A23 (reconciliation contact); spec §3 H-13.
- **Owner decisions applied:** keep minimal; prefer existing jsonb; tenant isolation is a trust boundary (composite FKs, RLS on every new table); supplier messages always human-tapped (AD10), so consent is recorded but never auto-collected.

## 5. Acceptance criteria (the exact proposal)
1. **`autonomy_grants`** (AU-16 writes, H-12 reads):
   ```sql
   CREATE TABLE "autonomy_grants" (
     "id" uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     "restaurant_id" uuid NOT NULL REFERENCES "restaurants"("id") ON DELETE CASCADE,
     "supplier_id" uuid NOT NULL,
     "max_agorot" bigint NOT NULL CHECK ("max_agorot" > 0 AND "max_agorot" <= 30000),   -- AD7 cap ₪300
     "types" text[] NOT NULL CHECK ("types" <@ ARRAY['PRICE_HIGHER','QTY_SHORT','QTY_OVER']::text[] AND cardinality("types") > 0),
     "basis" jsonb NOT NULL DEFAULT '{}'::jsonb,        -- eligibility snapshot shown at grant: N clean, window, gap rate
     "granted_by" uuid REFERENCES "users"("id") ON DELETE SET NULL,
     "granted_at" timestamptz NOT NULL DEFAULT now(),
     "revoked_at" timestamptz,
     "revoked_by" uuid REFERENCES "users"("id") ON DELETE SET NULL,
     "revoke_reason" varchar(16) CHECK ("revoke_reason" IN ('owner','reversal','bank_change','supplier_off')),
     "created_at" timestamptz NOT NULL DEFAULT now(),
     "updated_at" timestamptz NOT NULL DEFAULT now(),
     CONSTRAINT "autonomy_grants_supplier_same_tenant_fk" FOREIGN KEY ("supplier_id","restaurant_id")
       REFERENCES "suppliers"("id","restaurant_id") ON DELETE CASCADE,
     CONSTRAINT "autonomy_grants_revoked_pair" CHECK (("revoked_at" IS NULL) = ("revoke_reason" IS NULL))
   );
   CREATE UNIQUE INDEX "autonomy_grants_one_active" ON "autonomy_grants" ("restaurant_id","supplier_id") WHERE "revoked_at" IS NULL;
   CREATE INDEX "autonomy_grants_granted_by_idx" ON "autonomy_grants" ("granted_by");
   CREATE INDEX "autonomy_grants_revoked_by_idx" ON "autonomy_grants" ("revoked_by");
   ```
   Plus the `updated_at` trigger (doctor), the `UNIQUE (id, restaurant_id)` on `suppliers` if 0048/0050 did not add it (check first), RLS policy via the 0002 array. Who granted is also in `audit_log` (`autonomy.granted` / `autonomy.revoked`, AU-16).
2. **`claim_replies`** (AU-17 writes; a human confirms what it proposes):
   ```sql
   CREATE TABLE "claim_replies" (
     "id" uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     "restaurant_id" uuid NOT NULL REFERENCES "restaurants"("id") ON DELETE CASCADE,
     "supplier_id" uuid NOT NULL,
     "letter_id" uuid,                                   -- G-03 claim_letters, same-tenant FK when present
     "claim_ids" uuid[] NOT NULL DEFAULT '{}',           -- the open claims the reply was matched to (app-checked, tenant-scoped)
     "channel" varchar(16) NOT NULL CHECK ("channel" IN ('email','whatsapp','portal','manual')),
     "ingest_message_id" uuid,                           -- same-tenant FK → ingest_messages(id, restaurant_id)
     "received_at" timestamptz NOT NULL,
     "body_excerpt" text CHECK (char_length("body_excerpt") <= 1000),
     "tag" varchar(16) NOT NULL CHECK ("tag" IN ('accepted','credit_promised','disputed','question','unrelated','unknown')),
     "confidence" numeric(4,3) CHECK ("confidence" BETWEEN 0 AND 1),
     "classifier" varchar(16) NOT NULL CHECK ("classifier" IN ('rules','assistant','portal','human')),
     "proposed_status" varchar(16),                      -- a RecoveryStatus; never 'credited' or 'recovered'
     "decision" varchar(16) CHECK ("decision" IN ('confirmed','dismissed')),
     "decided_by" uuid REFERENCES "users"("id") ON DELETE SET NULL,
     "decided_at" timestamptz,
     "created_at" timestamptz NOT NULL DEFAULT now(),
     "updated_at" timestamptz NOT NULL DEFAULT now(),
     CONSTRAINT "claim_replies_supplier_same_tenant_fk" FOREIGN KEY ("supplier_id","restaurant_id") REFERENCES "suppliers"("id","restaurant_id") ON DELETE CASCADE,
     CONSTRAINT "claim_replies_message_same_tenant_fk" FOREIGN KEY ("ingest_message_id","restaurant_id") REFERENCES "ingest_messages"("id","restaurant_id") ON DELETE SET NULL ("ingest_message_id"),
     CONSTRAINT "claim_replies_no_money_state" CHECK ("proposed_status" IS NULL OR "proposed_status" IN ('acknowledged','disputed','letter_sent')),
     CONSTRAINT "claim_replies_decision_pair" CHECK (("decision" IS NULL) = ("decided_at" IS NULL))
   );
   CREATE UNIQUE INDEX "claim_replies_message_uq" ON "claim_replies" ("restaurant_id","ingest_message_id") WHERE "ingest_message_id" IS NOT NULL;
   CREATE INDEX "claim_replies_supplier_idx" ON "claim_replies" ("supplier_id","restaurant_id","received_at");
   CREATE INDEX "claim_replies_letter_idx" ON "claim_replies" ("letter_id","restaurant_id");
   CREATE INDEX "claim_replies_decided_by_idx" ON "claim_replies" ("decided_by");
   ```
   `ON DELETE SET NULL (col)` needs Postgres 15+ (CI runs 16); if `ingest_messages` lacks `UNIQUE (id, restaurant_id)`, add it in this file. The 1,000-character excerpt cap and a retention note ("purged with the ingest message", W2-14 DSR) keep personal data minimal.
3. **Supplier columns** (all nullable, no default, meaning-neutral for existing rows):
   - `suppliers.reconciliation_email text`, `suppliers.reconciliation_whatsapp varchar(32)` (AU-18's missing-documents ask, AU-17 statements; fallback to `contact_*` when null);
   - `suppliers.whatsapp_opt_in_at timestamptz`, `suppliers.whatsapp_opt_in_source varchar(16) CHECK IN ('portal','written','verbal_logged')` (AU-17 refuses a server WhatsApp to a supplier without it; e-mail needs none).
4. **What stays out of the schema (listed in the PR body):**
   - automation on/off and parameters → `restaurants.settings.automations` jsonb (AU-01 `automationOption`), incl. `supplierAutonomy`, `supplierSend`, `missingDocsReport`, `weeklyDigest`, `orderCutoffPush`, `allocationCountdown`, `masavFile`;
   - Masav institution data (non-secret: institute/sender code, short name) → `restaurants.settings.masav` jsonb (AU-19); supplier bank numbers stay in H-03's encrypted `supplier_bank_accounts`;
   - Masav file runs → **`audit_log` only** (`payments.masav_built` already carries `masavRunId`, `sha256`, `invoiceIds`, `totalAgorot`; AU-19 §5.3). Not H-03's `export_runs`: it has no `kind` or `sha256` column (`format` CHECK, `mode IN ('new_only','all')`, `range_from/range_to`; `docs/ux/wave2/H-03.md:105`), a Masav run fits neither mode nor a date range, and `export_run_invoices` rows would make the invoices read as "exported to bookkeeping" for AU-12 and W2-14. H-13 therefore widens nothing in `export_runs`;
   - bank-statement evidence → `audit_log` rows `recovery.bank_evidence` `{fileSha256, lineDate, amountAgorot, refHash}` (AU-19 keeps no statement file and no statement table);
   - missing-documents report snapshots → none (computed on demand; the e-mail is the record);
   - autonomy reversals, request-sent markers, KPI events → `audit_log` with `automationId` (README §4 rule 8).
5. **AU-07 telemetry:** on train A AU-07 needs no new column (it derives from `audit_log`, `activity_events`, `notifications_outbox`, `recovery_claims`). If AU-07's PR names one (e.g. first-opened-at per document), it is appended to this batch as a nullable column, never a local edit.
6. **`approval_rules` is not reused** (stated in the PR): it has no supplier FK (a supplier id inside jsonlogic is not tenant-checked by the database), no grantor, no revocation stamp, and its `auto_action` would invite a waive. It stays as is; no drop.
7. **RLS and attack probes:** both tables in the 0002 array; `check-rls` green; `rls.attack.test.ts` gains one raw probe block per table (GUC=A sees only A; insert with B's `supplier_id` fails on the composite FK); `cross-tenant.attack.test.ts` unchanged (no procedure here).
