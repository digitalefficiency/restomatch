# G-04 · Match-input truth: only counted lines, no draft POs, closed POs still match
**One line:** the 3-way match reads only what someone actually counted, on receipts that are closed, against POs that are real. Today:
- a pending receipt with 5 of 12 lines autosaved (W1-06 saves on every change) feeds 7 lines of "received 0" to the engine, so the leak jumps by whole lines while the receiver is still at the door;
- a receiver can open a receipt on a manager's **draft** PO and erase the owner's UNORDERED_ARRIVAL hold;
- a MarketMan/Zester PO that syncs as `closed` before its invoice arrives is never discovered, so that invoice goes unchecked;
- a rejection is subtracted twice by the stock readers.

This fixes the inputs only. The engine already skips a line with no count (`engine.ts:256`, `if (gr)`).

**Owner agent:** matching-engine-guardian (leak-economist signs the before/after ₪ diff; tenant-security-warden reviews the pinned-PO change). **Device:** both (server-only, no UI). **Effort:** M. **humanPR:** no (no immutable file. It changes which invoices are matched, so the ₪ diff is signed, MASTER-PLAN §5 rule 4).

## 5. Acceptance criteria
