# G-05 · Write-path kernel: guarded transitions, safe replay, domain events
**One line:** one transition authority for invoice, discrepancy and recovery-claim state: a guarded `UPDATE … WHERE status = ANY(from)`, CONFLICT naming who changed the row and when, replay-safe retries, one audit row and one domain event per move. A stale screen or a double tap can then never mark a ₪ claim paid, waived or recovered by accident. Today a naive "paid" erases ₪100 of claims and drops "caught before payment" from ₪296 to ₪196, and 33 paid lab invoices carry ₪1,758.58 of open claims. **Owner agent:** web-feature-engineer (tenant-security-warden reviews; matching-engine-guardian consulted on predicates). **Device:** both (server-only, no UI). **Effort:** L. Split it into 2–3 PRs if the 2-retry cap is at risk (MASTER-PLAN risk 11). **humanPR:** no.

## 5. Acceptance criteria
1. `lifecycle/kernel.ts`: `transition(tx, machine, { id, restaurantId, event, expectedFrom?, actorId, payload })` runs one guarded `UPDATE … WHERE id AND restaurant_id AND status = ANY(from) RETURNING`.
   - Zero rows and the row already sits in the target with an equal payload → **success** (replay-safe), with no second audit row.
   - Zero rows otherwise → `TRPCError CONFLICT` with `appParams { currentStatus, actorName, at }`, and **no** audit row.
   - Each moved entity gets exactly one `audit_log` row, then `emit()`.
2. Machines with edge metadata `{ kind: forward|side|terminal|reopen, requiresReason, undoable }`:
   - **recovery**: equal to today's `RECOVERY_TRANSITIONS`, as a table test against `recovery/lifecycle.ts`. `written_off` reopens, and only `recovered` is terminal. `credited` is entered only via a credit note.
   - **discrepancy**: from `open|escalated` only. The decision is recorded in `discrepancies.decision` (G-03) or, interim, in `audit.after.decision`.
   - **invoice**: `approve_for_payment`, `mark_paid`, `unmark`, `rematch_lock`, `external_sync`, plus the OCR and match events (`ocr_parsed`, `match_completed`). `initial: ['ocr_pending']`.
3. Batch: `transitionMany(tx, machine, { items: [{ id, expectedStatus }], guard? })` is all-or-nothing and returns per-item `CONFLICT | REFUSED` detail. The optional `guard(item)` lets W2-04 enforce, on the server, that bulk approve is ≤ ₪200 per invoice and that blocking items are never bulk-approved (owner decision). The kernel never hard-codes those caps.
4. Owner decision, payment: `mark_paid` and `unmark` touch only `invoices`. Test: `recovery_claims`, `discrepancies` and letter inputs hash-equal before and after. A paid invoice keeps its claims. The kernel stamps the event time, so "נתפס" can be measured at decision time against payment time (G-14 computes it). Until H-03 is deployed, `mark_paid` is defined but adopters must not enable it (W2-03 rule).
5. Named predicates in `lifecycle/predicates.ts`, as two separate predicates (never one "settled" set). `disputed` is covered.
   - `INVOICE_REMATCH_LOCKED` = `{approved, paid}`.
   - `INVOICE_CHECKED` = SQL `EXISTS (select 1 from match_runs …)`, never `invoices.status = 'matched'`.
6. `invoices/state.ts` composes W2-09a's CTE with `match_runs` and claims into `in_ocr | awaiting_count | awaiting_link | clean | flagged_open | claim_open | held_duplicate | approved | paid`. Parity test on the lab month (`DEMO_TODAY=2026-10-25`): the counts equal the hero's pending and awaiting counts and the pay-run buckets.
7. `lib/idempotency.ts`: `withIdempotency(ctx, { key, procedure }, fn)`:
   - the same key and user with the same request hash → the recorded response;
   - the same key with a different hash → CONFLICT;
   - stored in `idempotency_keys` (G-03), or interim in the audit row's `after.clientMutationId`.
8. `events/**`:
   - a typed `DomainEvent` union: `discrepancy.escalated`, `supplier.answered`, `receipt.closed_with_exceptions`, `invoice.ocr_failed`, plus one per transition;
   - `emit()` runs each effect in a savepoint (`tx.transaction`), so a failing effect is logged and **never** rolls back or silently voids the decision;
   - effects are inserts only.
9. `activity.ts` writes kind `event` with `metadata.kind` once G-03's enum value exists. The 6 existing kinds keep their exact behaviour (snapshot test).
10. Guard test:
    - no invoice or discrepancy status literal arrays outside `*/lifecycle.ts`, `lifecycle/**` and the explicit allow-list in §1.9 (each entry carries its owner id);
    - every `invoice_status` and `resolution_status` value is in `initial ∪ targets`.
11. No ₪ moves: the demo invariants are unchanged (no adopter is switched in this package), and the leak canary is green.
