# G-08 · Product links with provenance: a guess never becomes certainty
**One line:** one link policy, `decideLink` → `auto | review | new`, shared by the catalog import, OCR and order capture. A guessed link never becomes an alias that later auto-resolves every invoice. For example, `פלפל אדום חריף` linked at 0.667 to `פלפל אדום` and saved as certain sends every future line of that supplier to the wrong product. That creates phantom price leaks or hides real ones, and the wrong item's price also fills expected prices on orders and fires price alerts (catalog-01, P0). It also ships a read-only remediation report for links already guessed. **Owner agent:** ocr-procurement-engineer (leak-economist signs the policy table). **Device:** both (server-only; no screen of its own). **Effort:** M. **humanPR:** no.

## 5. Acceptance criteria
1. `packages/catalog/src/linkPolicy.ts` is **pure**: no db import, structural types only, so `@restomatch/ocr` can satisfy it without a new dependency. It exports:
   `decideLink(candidates: LinkCandidate[], row: { unitPack: 'match'|'mismatch'|'unknown' }) → { decision: 'auto'|'review'|'new'; productId: string|null; reasons: ReviewReason[]; suggestions: LinkCandidate[] (≤3) }`,
   where `LinkCandidate = { productId, canonicalName, confidence, matchedBy, provenance?: 'human'|'exactKey'|'newProduct'|'guess'|'legacy' }`.
   - `auto`: an exact key, meaning `matchedBy` is `sku` or `barcode`, or an alias with provenance `human|exactKey|newProduct`; or `confidence ≥ 0.95` **and** `unitPack = 'match'`.
   - `review`: the top candidate is ≥ `REVIEW_FLOOR` (0.6) but doesn't qualify for auto (`MEDIUM_CONFIDENCE`, `UNIT_MISMATCH`, `PACK_MISMATCH`, `UNKNOWN_UNIT`).
   - `new`: below the floor, or no candidate.
   - The thresholds move from `commit.ts` into this file as exported constants. Leak-economist signs the table in the PR.
2. `commitCatalogRows` calls `decideLink`, and its behaviour on today's `catalog-commit.test.ts` suite is unchanged, except one stricter case. An `auto` link that came from embedding or fuzzy (not an exact key) **does not** call `recordConfirmedMatch`. It may learn a *suggested* alias via a new `recordSuggestedAlias` at `min(conf, 0.900)` (interim) or `source = 'import_guess'` (after G-03). `catalog-commit.test.ts:100` is updated to this stricter expectation; say so in the PR.
3. `recordConfirmedMatch` requires `provenance: 'human'|'exactKey'|'newProduct'` **at the type level**, with no `'1.000'` default. `human` → 1.000, the other two → 0.999 (and `source` after G-03). Review rows never reach it. The call sites:
   - `mapping.ts:386` and `catalog.ts:706` pass `'human'`;
   - `commit.ts` passes `'newProduct'` or `'exactKey'`;
   - `matcher.test.ts` is updated.
4. `matchByAlias` and both branches of `matchBySku` return the **stored** alias confidence and a `provenance` derived by `aliasProvenance`, instead of a hard-coded 1.0. The catalog-item SKU branch (170-195) returns `matchedBy: 'sku'` (an exact key) with confidence 0.999. A legacy guessed product link on a catalog item is what the remediation report lists (§5.7).
5. `runOcrPipeline` options gain an optional `decideLink?: (c, row) => LinkDecision`, declared structurally in `pipeline.ts`.
   - When it is injected, `enrichLine` uses it with `unitPack: 'unknown'`, because OCR candidates carry no unit.
   - When it isn't, the default auto-links **only** `matchedBy ∈ {sku, barcode}`, or `alias` with `confidence ≥ 0.999`. This is the provable exact-key subset of `decideLink`. Everything else keeps `productId: null` with candidates (review).
   - Don't add `@restomatch/catalog` to `packages/ocr/package.json`.
6. Parity test: the same candidate sets through `commitCatalogRows`, `runOcrPipeline` (with `decideLink` injected, and with the default) and a direct `decideLink` call give the same decision. For the default, it gives a subset: `auto` only where `decideLink` says `auto`.
7. `catalog/remediation.ts` exports `aliasRemediationReport(db, restaurantId)`, **read only**. It lists:
   - catalog items from an import whose product predates the import and whose name similarity is < 0.9;
   - the aliases created with them;
   - draft or open POs and open price alerts priced from those items, with ₪ per line formatted at display only.

   `apps/worker/scripts/catalog-alias-remediation.ts` prints it (CSV + summary) and writes nothing: run it under a read-only transaction (`SET TRANSACTION READ ONLY`). Decision 24: a person confirms each unlink after the pilot. The script offers no unlink flag.
8. Review rows keep `product_id NULL`, and suggestions (top 3) are computed on read. Two acceptable paths:
   - extend `mapping.unmapped` to also return catalog-item review rows, keyed by `(supplierId, supplierSku ?? rawName)`, with `suggestions[]`, accepted through `mapping.confirm` (confidence 1, re-match as today);
   - or, if that grows beyond about 80 lines, ship the SKU-keyed rows now and ask the orchestrator to move name-keyed review to W3-10. Don't build UI.
9. Golden tests:
   - `פלפל אדום חריף` against `פלפל אדום` → `product_id` NULL, no alias, 1–3 suggestions;
   - a unit mismatch at ≥ 0.9 → review;
   - a type test where `recordConfirmedMatch` without `provenance` fails tsc (`// @ts-expect-error`).
