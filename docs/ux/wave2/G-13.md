## 5. Acceptance criteria
1. **`parseDecimalInput(raw, kind, opts?)`**, `kind: 'ils' | 'unitPrice' | 'qty' | 'percent'`, returns `{kind:'ok', value, agorot | priceUnits | milli | basisPoints}` · `{kind:'empty'}` · `{kind:'ambiguous', raw, reason}` · `{kind:'invalid', raw, reason}`; never null for a non-empty cell. Scales: ils 2 (agorot), unitPrice 4 (price units = 1/100 agorot), qty 3 (milli), percent 2 (bp). Built on `parseNumberInput`, whose grammar does not change. The DEEP-FIX table is the test; at least:

   | Input | Kind | Result |
   |---|---|---|
   | '1,250' | ils | 125000 agorot |
   | '1,250' | unitPrice | 12500000 |
   | '1,250' | qty | ambiguous ("thousands or decimal comma") |
   | '₪1,250', '₪ 2,400' | ils | 125000, 240000 |
   | '1,250,000' | ils | 125000000 |
   | '12,90' | ils | 1290 |
   | '1,250.00' | ils | 125000 |
   | '0,250' | qty | 250 milli |
   | '2,5' | qty | 2500 milli |
   | '1.250' | ils | ambiguous (3 decimals) |
   | '1.250' | unitPrice | 12500 |
   | '1.234,50' | any | ok only with `decimal:'comma'`, else invalid |
   | '-5' | any | invalid unless `negative:true` |
