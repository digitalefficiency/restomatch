# H-01 · `formatIls` `signDisplay` option
**One line:** an additive `signDisplay` option on the frozen `formatIls()`, so a signed ₪ move ("+₪3.41", "−₪100") comes from Intl instead of hand-concatenated `'+'`. Hand-built signs land on the wrong side in RTL ("+ 3.41₪", "12%+"), and a price rise can read as a fall. - **The proposed diff (≈10 lines):**
  ```ts
  export type IlsSignDisplay = 'auto' | 'exceptZero' | 'never';

  export function formatIls(
    value: number,
    opts: { maximumFractionDigits?: number; locale?: Locale; signDisplay?: IlsSignDisplay } = {},
  ): string {
    return new Intl.NumberFormat(intlLocaleOf(opts.locale ?? 'he'), {
      style: 'currency',
      currency: 'ILS',
      maximumFractionDigits: opts.maximumFractionDigits ?? 0,
      ...(opts.signDisplay ? { signDisplay: opts.signDisplay } : {}),
    }).format(value);
  }
  ```
  Spread the option only when given, so the default `Intl` options object is unchanged. Add a JSDoc line: "a sign is not a meaning: direction words/arrows stay in `<Delta>`/`<PriceMove>` (R-4); use `exceptZero` for signed deltas, `never` for a credit shown with the word זיכוי".

## 5. Acceptance criteria
1. The option is additive: `signDisplay?: 'auto' | 'exceptZero' | 'never'`. No other signature change, and no new export besides the `IlsSignDisplay` type.
2. Default output is byte-identical. A committed snapshot of 200 values × {he, en} × {0, 2, 4 dp} passes **before and after** the change. The values come from a deterministic list: 0, −0, ±0.004, ±0.005, ±0.01, ±1, ±99.995, ±1,234.5, ±1e6, ±99,999,999.99, plus a seeded LCG fill to 200, and also NaN and ±Infinity. Commit order: (a) the snapshot test on the unchanged util, green; (b) the util change with the snapshot untouched, still green. `auto` produces output identical to the default (asserted).
3. In `he`, `exceptZero` puts the sign before the currency inside one isolate:
   - unit test: the output matches `/^‏‎[+-]\d/`, and 0 has no sign;
   - Playwright bbox, with the string rendered inside one `<bdi>` in a `dir="rtl"` paragraph: left to right the order is ₪, then the sign, then the first digit. The sign is adjacent to the first digit (gap < 0.3 em) and is never right of the last digit (the "12%+" failure).
   In `en`, the output is `+₪3.41` / `-₪3.41`.
4. `never` gives the absolute value with no sign in both locales: −120 → `‏120 ₪` / `₪120`.
5. `money-parity.test.ts` stays green unchanged. A new parity row states that the server twin has no `signDisplay` yet (G-13), written as a skipped-with-reason case, not a silent omission.
