## 4. What to fix and build
- **Findings:** none directly. This is the enabler for DoD-8 in every wave-2/3 package that adds a procedure (IMPLEMENTATION-PLAN §0.2 rule 6).
- **Deep-fix class:** none of the 15 classes. It is the precondition for class 13 (capability tests per procedure, G-07) and for every new procedure in classes 8 and 14.
- **Part B amendments:** none for W2-01. Downstream, GAP-PACKAGES gives G-07 and G-14 their own fragments, `coverage/G-07.ts` and `coverage/G-14.ts`.
- **Build:**
  1. `coverage/index.ts` exports:
     - `type CoverageFragment = Readonly<Record<string, string>>`;
     - `loadFragments()`, which uses `import.meta.glob<{ default: CoverageFragment }>(['./*.ts', '!./index.ts'], { eager: true })`;
     - `mergeCoverage(base, fragments)`;
     - `diffCoverage(registered, declared): { missing; stale }`.
  2. In the attack file, rename the literal to `BASE_COVERAGE` (entries unchanged, in place). Then add `const COVERAGE = mergeCoverage(BASE_COVERAGE, loadFragments())`. The completeness test keeps `expect(registered).toEqual(declared)`, now over the merged map, and reports `diffCoverage` output in its message.
  3. `mergeCoverage` **throws** (the suite fails) on any of these:
     - a key in two sources (base↔fragment or fragment↔fragment), naming both sources. A fragment can never override, and so never downgrade, a base entry;
     - a fragment file name outside `^(W[1-4]-\d{2}[a-z]?|G-\d{2}|H-\d{2})\.ts$`;
     - a fragment value that is not `attack — <file>.test.ts: <claim>` / `isolation — <file>.test.ts: <claim>`, or a justification of at least 30 characters without "TODO". A bare `'attack'` or `'isolation'` is allowed only in the base, because it means "a test below in this file";
     - a fragment value whose named `<file>.test.ts` does not exist under `src/__tests__/`.
  4. Ratchet: `expect(Object.keys(BASE_COVERAGE).length).toBeGreaterThanOrEqual(<count on main>)`. The base can grow, but a human must still add those entries.
  5. `coverage/README.md` (≤40 lines) covers:
     - each package owns `coverage/<package-id>.ts`;
     - a copy-paste template;
     - the value format;
     - "never re-declare a base key; strengthening a base entry is a human PR";
     - where the attack test goes: in the package's own `*.attack.test.ts`, never in the base file.

## 5. Acceptance criteria
1. `COVERAGE = mergeCoverage(BASE_COVERAGE, loadFragments())`, never a plain object spread (a spread lets a fragment silently override a base entry; see §8). `loadFragments()` uses `import.meta.glob(['./*.ts', '!./index.ts'], { eager: true })` inside `coverage/index.ts`, or the documented fallback in §8.
2. No entry is removed or downgraded:
   - `git diff` of the 201 base lines shows only the const rename;
   - every `it(...)` body is byte-identical (check it with `git diff --stat` plus a grep of the changed hunks).
3. The completeness test still fails for an undeclared procedure, and still fails for a stale entry. A negative test proves both using `diffCoverage` with a synthetic `ghost.proc`.
4. A collision (a fragment re-declaring `activity.feed`) makes the suite fail and names both sources. So does a fragment with a bare `'attack'`, a missing test file, or a bad file name. Each case is a negative test.
5. With zero fragments on disk, the merged map equals the base and the full `cross-tenant.attack.test.ts` passes unchanged against the migrated test DB.
6. The README states that each package owns `coverage/<package-id>.ts`. It contains the template and the four rejection rules.
7. `pnpm --filter @restomatch/api typecheck` is green with no new dependency. Only the package that owns `package.json` in this wave may add one, and that is W2-15.
8. The PR body has the "Human-PR proposal" heading, a two-line rationale ("restructure, not weaken") and the exact merge instruction: "merge first in wave 2; then announce to all W2 sessions to rebase".
