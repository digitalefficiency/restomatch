# W2-02 · Invoice register, invoice cockpit and intake

A DataTable register of every invoice by canonical state, a cockpit that puts the document beside the ordered/received/billed lines with the ₪ gap, and an intake inbox you can triage. ## 5. Acceptance criteria
1. **The register.** `/dashboard/invoices` is a DataTable register with `ViewTabs` and counts: לבדיקה · ממתינות לשיוך (T4, neutral) · הותאמו · בהשהיה · שולמו · ללא מספר הקצאה · נכנסות (today's inbox).
   - Columns: date (dd.MM.yyyy) · supplier · number `<Token kind="invoice">` · ₪ incl. VAT · due date (`DeadlineChip`) · ₪ gap · `StatusChip` · allocation ✓/✗.
   - A `TotalsRow`, where the visible total = Σ visible rows. `?sel=` opens a split pane. Numbers are physically right-aligned in he and en.
   - On the lab, the tab counts equal G-05's state parity numbers (the hero pending/awaiting and the pay-run buckets).
2. **`invoices.detail`.** It returns status, PO and GR refs (`<Token>`), and lines joined to their discrepancies: expected with its source and date, actual, Δ₪, tolerance text as persisted. It also carries OCR line confidence, `duplicateOf` and the VAT-at-risk row.
   - Receiver and chef get no ₪ from it: for roles without `money.view` it returns no `*Ils`/price fields (G-07 `redactPrices`), with a test. The chef gets FORBIDDEN.
3. **The cockpit (≥1024 px).** A 44/56 split with the document at the start edge: zoom 50–400 %, rotate, page thumbnails.
   - Beside it, the three-way table: הוזמן · התקבל · חויב · מחיר צפוי (מקור, תאריך) · מחיר בחשבונית · פער ₪.
   - Flagged lines are expanded with the W1-07 verbs (import `apps/web/app/dashboard/approvals/vocab.ts` read-only).
   - A sticky "החליטו על N פערים · ₪X" opens `/dashboard/approvals?invoice=<id>` (W2-04 adds the param). A `DocumentFlow` strip links PO → קבלת סחורה → חשבונית → דרישת זיכוי.
4. **OCR edit mode.** "ערכו נתוני סריקה" is an explicit mode. Saving re-matches automatically (no separate rerun button) and shows "₪ לפני → אחרי" from `match.runForInvoice`, which returns `{before, after}` agorot.
   - Money inputs use `MoneyInput`, dates use `DateField`, and there is no `type=number|date`.
   - Low-confidence OCR values (`ocrConfidenceLine` below the threshold) carry a "לבדיקה" marker.
   - The reconciliation line "שורות = לפני מע״מ ✓ · מע״מ X% ✓" takes X from the restaurant `vat_rate` the engine used. The ✓/✗ come from the persisted match result (no TOTAL_MISMATCH / VAT_MISMATCH), never from a UI-side tolerance.
5. **Phone (390).** A `SegmentedControl` "מסמך | שורות", then line cards. No ₪ is clipped, there is no horizontal scroll, and the header form is collapsed.
6. **Navigation.**
   - The breadcrumb follows `?from=` (approvals / pay-run / inbox / register / leaks).
   - The h1 and `<title>` read "MF-24950 · דגי הים התיכון".
   - `[` and `]` step through the originating queue (`KeyboardEvent.code`, inactive in inputs).
   - Loading: one layout-true `loading.tsx` per route. `ensureEnglish` never blocks the first paint.
7. **Intake.**
   - Image/PDF previews come from `ingest.documentPreview`: a ≤60 s signed URL for a tenant-checked storage path, PDFs in `<iframe sandbox>`.
   - Bulk "פענחו N" goes through a BatchBar. Block rows don't apply, so there is no cap; the action isn't approval.
   - The OCR outcome shows inline (supplier, ₪, lines, or the failure reason).
   - Revoke and remove-sender go through `ConfirmDialog` naming the channel or sender, show a real error toast on failure, and never claim false success.
   - Clipboard: "הועתק" only when the promise resolves, otherwise "העתיקו ידנית" with the secret selected.
   - Channels and the allow-list move to `/dashboard/settings` links, with no inline config cards (W2-14 owns settings; you only link to it).
   - The page has a real h1, real `Tabs` and a correct select name. Only the touched row refetches; no `router.refresh()`.
8. **`/scans/[id]`.** A minimal in-shell original view with "← חזרה לחשבונית", tokens only (no hex, no `text-[10px]`, no perpetual ping) and the `LegalLinks` footer.
   - Role rule = invoices: the chef gets 404 on the page and on `file/route.ts` (owner, manager, receiver, bookkeeper allowed). An e2e checks both.

10. **Nav.** The bookkeeper bar slot 4 "invoices" points to `/dashboard/invoices`, which becomes a nav item for owner, manager and bookkeeper. The register is not in the receiver or chef nav (owner decision: no purchase ₪ for them).
