## 5. Acceptance criteria
1. Effective values are shown. A new `settings.effective` (memberProcedure, read-only) returns `{ key: { value, isDefault } }` from `resolveTolerances`, `resolveApprovalThresholds` and `DEFAULT_REVIEW_THRESHOLD`, with no redefinition. On the lab seed, each input shows its value with a chip "ברירת מחדל" or "הותאם". For example "חשבונית בלי הזמנה מעל ₪5,000 עוברת לאישור" (value via `formatIls()`/`<Money>`). Each group has one rule sentence.
2. `settings.update` accepts `null` per key, which removes the override and restores the default. A test proves the JSONB key is gone and the other keys survive.
3. `recordAudit` (`settings.updated`, `settings.profile_updated`) runs on `update`/`updateProfile` with before and after. A per-section "היסטוריית שינויים" drawer reads them through a new finance-tier `settings.history`.
4. VAT is read-only "18% · שיעור ארצי מ-01.01.2025", with a "שנה…" dialog that names the effect on the leak ₪. Timezone is a select (Israel-only).
5. ₪ and % inputs are `type="text" inputMode="decimal"` with an end adornment, and accept "7,5". Errors read "אחוז בין 0 ל-100". Numbers are physically right-aligned (`NUM_ALIGN`; owner decision). There is no `type=number` anywhere in the 4 routes.
6. Team role change:
   - it is staged: the row shows "שינוי: ‹ישן› ← ‹חדש› · [שמור] [בטל]";
   - promoting to owner, or downgrading owner, manager or bookkeeper, opens a ConfirmDialog listing the powers gained or lost (from `CAP`);
   - the select on your own row is disabled;
   - the result shows inline on the row, and pending state is per row.
   A stale role → CONFLICT naming who changed it.
7. The role picker sheet has one line per role. Names use noun forms with no slash form in `he` (DoD-6; e.g. "הנהלת חשבונות — קוראת הכל ועורכת כרטיסי חשבון"). A "מה מותר?" matrix is generated server-side from `CAP` + `ROUTE_ROLES`, and a unit test asserts matrix == `CAP`.
