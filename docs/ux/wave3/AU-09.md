# AU-09 · Consolidated autopilot: propose the delivery-note set and explain every shekel of the difference
**One line:** when a חשבונית מרכזת arrives, the bookkeeper opens it to a ready proposal of which delivery notes it bills and a split of every shekel of the difference by cause; they confirm the set, and nothing enters the leak until the human-PR accept path (H-08) exists.
- **What they see:** "17 תעודות משלוח מכסות את החשבונית · הפרש ₪212.40 = מחיר ₪180.00 · כמות ₪36.00 · הנחה −₪3.60 · לא מוסבר ₪0.00"; or, when the paper lists no notes, the one set of open notes whose quantities fit the bill; or "יש 2 אפשרויות — בחרו".
- **Impact (assumption):** 3–5 consolidated invoices a month; the manual line-up falls from 20–45 min to ~5 min each = 0.2–0.75 h/week = ₪75–290/month time-₪ at ₪89/h (labour value; an external bookkeeper's fee falls only if the fee changes). Money-₪, separately: a note billed twice stopped before payment, ≈ ₪3,333 per event (average delivery), 0–1 per quarter, so ₪0–1,100/month expected, lumpy; shown as a T2 review item and pay-run hold, **never in the leak hero**.
- **Today:** the read-only proposal takes *every* uncovered note in the period (or the listed ones), shows one `differenceIls` with no cause split, cannot say "two sets fit", and a bookkeeper cannot record which set they checked. The lab carries ₪3,603 of consolidated spend outside the leak and a seeded ₪36.00 overcharge (excl. VAT) that must not move.
**Owner agent:** matching-engine-guardian (leak-economist signs the residual labels and the "never in the hero" rule; tenant-security-warden reviews the new procedures). **Device:** desktop (bookkeeper; phone read-only). **Effort:** L (2 PRs: a = pure set search + residual explainer, b = procedures + panel). **humanPR:** no for this package; the accept write that links notes and lets ₪ flow is **H-08** (human, `packages/matching/**` + H-03/H-04 columns).

## 5. Acceptance criteria
1. **Set search (pure).** `proposeNoteSets(input)` in `consolidatedPropose.ts`, input = invoice `{subtotalAgorot, lines by product: billedQty}` + candidate notes `{grId, number, receivedAt, valueAgorot, qtyByProduct}`; output `{mode, sets: Array<{grIds, qtyMisfit, valueGapAgorot}>, searched, truncated}`:
   - `mode 'listed'` when the invoice lists note numbers: the set is the listed notes found in the system (today's path), never searched;
   - `mode 'search'` otherwise: candidates = the supplier's uncovered notes in `candidatePeriods` (same loaders);
   - ranking: per-product quantity misfit first (Σ |billedQty − Σ receivedQty| in base units via the engine's `unitConversionFactor`), then |₪ gap|;
   - keep at most 3 sets within `SET_FIT_TOLERANCE` (a named constant: ₪1.00 or 0.1% of the subtotal, whichever is larger; matching-engine-guardian signs the value; it selects sets only and never changes a finding);
   - bounded: exact search up to `MAX_EXACT_NOTES = 24` candidates (meet-in-the-middle on agorot), above that a deterministic greedy by date with `truncated: true`; ≤ 300 ms on 60 candidates;
   - result `exact` (one set fits), `ambiguous` (≥2 sets fit, all returned), `none` (no fit: fall back to today's full-period set and say so).
2. **Residual by cause (pure).** `explainResidual(proposal)` over the `ConsolidatedProposal` of the chosen set, all in integer agorot, signed (+ = billed more):
   - `price` = Σ (billedPrice − poPrice) × qtyBilled;
   - `quantity` = Σ (qtyBilled − qtyReceived) × poPrice;
   - `discount` = Σ negative or "הנחה/discount" invoice lines;
   - `otherMonth` = value of notes flagged `note_other_month`;
   - `billedTwice` = the overlapping ₪ of `note_billed_twice`;
   - `notInSystem` = count of listed notes without a receipt (₪ unknown, never estimated);
   - `unexplained` = residual − Σ the ₪ causes, shown, never forced to 0.
   - Identity test: Σ causes + `unexplained` = `totals.differenceIls` exactly.
3. **Money truth unchanged.** For the same note set, `leakIls`, `claim`, `findings` and `products` equal today's `consolidatedProposal` output (snapshot on the lab and on `consolidated.test.ts` fixtures). The seeded overcharge stays ₪36.00 excl. VAT; no ריכוז gets a `match_runs` row; hero ₪759.54 unchanged.
4. **`consolidated.proposeSet`** (`financeProcedure`, query, flag-gated like `proposal`): `{invoiceId}` → `{mode, result, sets[], chosen: ConsolidatedProposal for sets[0], residual, flags: {otherMonth, notInSystem, billedTwice}, proposalStatus}`. Foreign `invoiceId` → NOT_FOUND (via `assertInvoiceOwned`). Receiver and chef FORBIDDEN.
5. **`consolidated.chooseSet`** (owner, manager, bookkeeper; `financeProcedure`): `{invoiceId, grIds, clientMutationId}` → one audit row `consolidated.set_chosen` with `after = {automationId: 'A14', grIds, mode, result, matchedProposal: boolean, residualAgorot}`. It validates every `grId` belongs to the restaurant and the invoice's supplier; it writes no invoice, receipt, discrepancy or claim. Replay → the recorded result.
6. **Panel.** Above today's tables: a state line
   - exact: "הצעה: 17 תעודות משלוח מכסות את החשבונית" (T4 neutral) + "אשרו את הסט";
   - ambiguous: "יש 2 אפשרויות שמתאימות לסכום — בחרו" with a side-by-side diff of the notes that differ (number, date, ₪);
   - none: "לא נמצא סט מדויק — מוצגות כל התעודות הפתוחות בתקופה" (warn text, no solid badge);
   then the residual strip "הפרש ₪212.40 = מחיר ₪180.00 · כמות ₪36.00 · הנחה −₪3.60 · לא מוסבר ₪0.00" with each cause a link to its rows; billed-twice as a T2 row "אפשר שחויב פעמיים · ₪X" (one CTA to the other invoice); `notInSystem` as "2 תעודות שלא נקלטו במערכת". After `chooseSet`: "נבדק ע״י <name> · <date>". Finance roles only (as today); light tokens; RTL; he/en parity.
