## 0. One line
Every ₪ of the monthly leak sits in exactly one money state, the states sum to the hero leak **to the agora**,
and one table (`DECISION_RULES` / `effectOf`) is the only place a status becomes a ₪ effect.

## 5. Acceptance (slice a)
1. `computeLeakLedger(db, rid, spec)` — one row per counting discrepancy (`LEAK_FILTER`) of the period with
   `capped_agorot`, `raw_agorot`, `invoice_paid`, `paid_at`, `claim_id`, `claim_status`, `credited_agorot`,
   `caught_before_payment`, `basis`, and one `money_state` ∈ `undecided · to_offset · to_send · requested ·
   disputed · credited · recovered · waived`.
2. **One allocator** per invoice cap (`round(total_incl_vat·100)`): tier 1 rows holding a live claim read the
   persisted `amount_agorot` (≤ raw); tier 2 other decided rows; tier 3 undecided rows get only what is left.
   Inside a tier: `(created_at, id)` — the order of `syncClaims`. All integer agorot.
3. `computeLeakPartition` → `{ states: Record<MoneyState, agorot>, totalAgorot, heroAgorot, driftAgorot }`;
   on every seeded month and the canary scenario `driftAgorot = 0`, i.e. **Σ states = hero, to the agora**.
4. `DECISION_RULES[type] = {allowed, primary, toStatus, effect}` over all 12 types + the system decision
   `tolerate`; `resolved` has a defined meaning; `effectOf(type, status|decision)` is the only status→₪ map,
   and the ledger's SQL state is generated from it (parity test).
5. "Caught before payment" = the detection (`created_at`) or decision (`resolved_at`) precedes `paid_at`;
   an unpaid invoice's leak is caught. Not `status <> 'paid'`.
6. `METRICS` registry: `leak.month`, `priceCreep.30d`, `supplierLeak.90d`, `atRisk.pending`,
   `claims.claimed|outstanding|returned`, `caught.open`, each `{window, basis, procedure, scope, drill}`;
   `metricValue(id, agorot)` = `{metric, agorot}`.
7. `coverage.ts` exports the W3-09 placeholder type + an empty computation; W3-09 fills it.
