## 5. Acceptance
- No code path marks a row `sent` unless a real provider accepted it; with no keys every channel ends `failed + skipped_no_provider` (`deliverOutboxRow` returns `skipped`). A row that can never go (a `role:` target, a broken template) is `rejected` without retry; a provider error throws and retries.
- A WhatsApp row carrying `payload.__waTemplate` is sent as `type:'template'` with the registered name, language `he`, and its params in order; an unknown template or a missing param throws (no free-text fallback to a supplier).
- A template whose param is money is refused for receiver/chef recipients (`payload.role`), mirroring G-06's redaction.
- `foldDigest` turns N `payload.digest` rows of one person/day into one message listing N items; ₪ never summed across items.
- Chase cadence: nothing before day 7 (owner rule "overdue after 7 days"); day 7, 14, 21 …; every chase is a draft awaiting a tap; the day-3 courtesy exists only behind `CHASE_COURTESY_DAY3 = false` and never says "באיחור".
- Human PR: `enqueueNotification` stores `attachments` under `payload.__attachments`; `markSent` keeps existing payload keys and adds `externalId`; `markSkippedNoProvider` writes `failed + skipped_no_provider`. `cron.ts` header no longer claims a `sync-platforms` schedule; no slot moves.
- Leak canary and both attack suites unmoved. No ₪ moves.
