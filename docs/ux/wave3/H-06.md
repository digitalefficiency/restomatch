# H-06ʰ · The supplier's reply link for a "מכתב בקשת זיכוי" (HUMAN-PR proposal)

**One line:** a 72 h, per-letter, signed link the restaurant attaches to its credit-request letter, so the supplier can answer each line ("מאשרים" / "נבדוק יחד") without an account, and the claim status moves by itself. A new public write path, so this whole package is a human-authored, warden-reviewed PR.

## 4. Slices
- **a · server + route + page (this PR).**
  1. `claimPortal/token.ts`: `c1.<payload>.<sig>` — payload `{r: restaurantId, s: supplierId, iat, exp}` base64url, HMAC-SHA256 with `CLAIM_PORTAL_SECRET`, `exp = iat + 72 h`. Constant-time verify; strict shape regex and a length cap before any crypto. Optional `c2` shape (orchestrator 7.11): the same payload plus a signed `letterId` for G-03's `claim_letters` (0071, deploys 24.11); `mintClaimLink({letterId})` emits it now, and scoping switches to per-letter (`claim_letters.id`) once that table is on `main` — the signature stays stateless. One link = one supplier's letter of one restaurant; its lines are that supplier's claims in `letter_sent` whose `letter_sent_at ≤ iat` (what the letter carried when the link was made). No DB row, no schema change.
  2. `claimPortal/service.ts`: `mintClaimLink`, `resolveClaimToken` (malformed / bad signature / unknown restaurant / `recovery` flag off / secret unset ⇒ `NOT_FOUND`, indistinguishable; a valid-but-expired link ⇒ `EXPIRED`), `loadClaimLetter` (a supplier-safe projection: no internal note, no discrepancy type code, no other supplier), `submitClaimAnswer` (per line `agree` → `acknowledged`, `check` → `disputed`, through `transitionClaim`; all lines in one tenant transaction; any line no longer `letter_sent` ⇒ the whole answer is refused `ALREADY_ANSWERED`; the supplier may name the credit-note number they will issue — it goes into the event note only, never into `credit_notes`: a credit is recorded by the restaurant from the real document).
  3. `apps/web/app/api/claims/[token]/route.ts`: `guardPublicRequest` with same-origin, a 16 KiB cap, a strict zod body, and **two** limiters: per IP (`rl:claim-portal-ip`) and per (IP, token-hash) (`rl:claim-portal`). The raw token never keys a limiter or a log.
  4. `apps/web/app/s/c/[token]/page.tsx`: the RTL page in partner wording (GLOSSARY §2), page views behind a per-IP view limiter, `noindex`, `no-store`, `referrer-policy: no-referrer`.
  5. `recovery.claimLink` mint procedure — **deferred to W2-10 / H-05ʰ** (it needs `api/routers/recovery.ts`, W3-11's file). Until then `mintClaimLink` is a server function with tests.
- **b · later:** credit-note file upload from the supplier (needs a storage bucket; Phase-6), the link inside H-05ʰ's send, and the owner's "the supplier answered" notice via `notify()`.

- **Hand-off to W3-11 (`recovery/service.ts`, not H-06's file; warden review 7.11):** (1) `syncClaims` re-opens a system write-off to `letter_sent` without re-stamping `letter_sent_at` (`service.ts:211-215`), so a link issued before the write-off can answer the re-opened line within its 72 h; re-stamp `letter_sent_at = now` on that re-open. (2) `transitionClaim` takes `input.at`; clamp `at ≥ now` for `letter_sent`, so a back-dated send cannot fall inside an older link. (3) Supplier replies use `actor_id` NULL like system events; tell them apart by the event note prefix "תשובת הספק בקישור" until a source column exists (a schema proposal for H-04ʰ).

## 5. Acceptance
- A link opens only its own restaurant + supplier, only within 72 h, and only while the secret is set and `recovery` is on. Tampering with any byte of the payload or the signature ⇒ 404 with the same body as an unknown link.
- Every line shows invoice number, date, item, and ₪ via `formatIls()`; no internal note, type code, status word or other supplier ever reaches the page or the JSON.
- Wording: "מכתב בקשת זיכוי", "בקשת זיכוי", "חשבונית זיכוי", "נבדוק יחד", "תודה"; never דרישה / תביעה / מחלוקת / חוב / באיחור / דליפה (checked by a unit test over the page strings).
- A second answer (or a replay) is refused; the claim status moves only `letter_sent → acknowledged | disputed`; ₪ figures never change (no `credited`, no amount write).
- POST: 405 on other methods, 403 cross-origin, 413 over the cap, 429 per IP and per token hash, 422 on unknown fields.
