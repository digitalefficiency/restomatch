## 4. Slices
- **a — field components (now):**
  - `ScanButton`: a 56 px thumb button. Detection behind a `BarcodeEngine` interface (`isSupported()`, `detect(source)`); `nativeBarcodeEngine` wraps `window.BarcodeDetector`; `resolveBarcodeEngine()` picks the first supported engine (ZXing joins the list later without an API change). Unsupported, camera denied or offline-without-engine → a manual code-entry sheet. Emits `onCode(code, { source: 'camera' | 'manual', format })`.
  - `MicButton`: speech-to-text via `SpeechRecognition` / `webkitSpeechRecognition` (default `he-IL`). Always shows the transcript for confirmation before calling `onTranscript` (acceptance: "transcript before any write"). Unsupported or denied → a typed-entry fallback; the button never disappears silently.
  - Both: ≥56 px, glove/glare friendly (solid fills, strong borders, ≥16 px input text, high-contrast tokens only), offline-safe (no network calls), RTL logical properties, AA. **No ₪ anywhere.** Nothing mounted in pages.
- **b — the rest (≥7.12):** manifest + shortcuts, `share_target`, install sheet, `storage.persist()`, VAPID UI per role/event, SW push deep links, `setAppBadge`, the 06:00 receiver brief, mount ScanButton/MicButton in receiving pages, `DocumentFlow` on the receipt summary, ZXing.

## 5. Acceptance (slice a)
- `ScanButton`/`MicButton` render a ≥56 px control (`min-h-14`), keyboard reachable, named via `aria-label`, state announced (`aria-live`).
- Native detector used when present; manual fallback when absent, denied or failing. No exception escapes to the page.
- MicButton never calls `onTranscript` without an explicit confirm.
- he/en key parity for `common.field.*`; no ₪, no hex, no `dir="ltr"`, logical properties only.
- Slice-b acceptance is the IMPLEMENTATION-PLAN W3-03 list (ScanButton jumps to the line in ≤400 ms on a Galaxy A14-class phone, etc.).
