## 4. Slices
**1 · Admin console (this PR)**
- a. Server: an `AdminReason` input (trimmed, 3–500 chars). Required on `assignPlan`, `setOverrides`, `setMemberRole`; optional on `setFeatures` (carve-out). Stored in the audit `after` as `reason`. No new procedure, so no COVERAGE change.
- b. UI: one shared `admin/_components/StagedChange.tsx`: a pending-change card that lists each field "לפני → אחרי", a required reason textarea, "אישור השינוי" (the one primary) and "ביטול". Plan, overrides and member role all stage first; nothing is written before confirm. The role `<select>` no longer writes on change.
- c. Admin uses dashboard primitives: drop `font-mono` / `uppercase tracking-wider` from Hebrew labels and headings on the pages and forms this package owns (numbers keep `tabular-nums`).
- d. Last, after AU-01 GREEN: "פיצ׳רים פעילים" per restaurant with its source (plan / override / flag / demo `all` / kill-switch), and `setFeatures` reason → required.

**2 · Integrations + settings (after W2-14)**
- "חיבורים" hub grouped הנהלת חשבונות · קופה · רכש · קליטת חשבוניות: status chip, last sync, plain-Hebrew last error + one fix CTA; nav dot only when action is needed; intake addresses live here; MarketMan / Zester get a real contact path.

- New procedures (if any) get `coverage/W3-07a.ts` (`git add -f`) + a cross-tenant attack test.

## 5. Acceptance
- An admin write without a reason (or < 3 chars after trim) is rejected `BAD_REQUEST` and changes nothing; with one, the audit row's `after.reason` equals the trimmed text.
- A non-admin still gets `FORBIDDEN` before input validation (attack suite unchanged and green).
- In the console no write happens until "אישור השינוי"; the card shows before → after for every changed field; "ביטול" restores the form.
- Hebrew-first RTL, AA pairs, no ₪ on these screens (plans show names only), no mono/tracking on Hebrew text in owned files.
