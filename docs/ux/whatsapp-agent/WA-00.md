# WA-00 · December "pull-only" owner pilot: read-only brief + Ask, no money, no templates, no new tables
**One line:** from late December, one or two owners (the RestoMatch owner on lab data, then the pilot restaurant's owner on their own data) can write to the RestoMatch WhatsApp number. They get the morning brief when they type "בוקר", and a short grounded answer to a leak question. They cannot take any action, money or otherwise. Every reply goes out inside the 24-hour window that the owner opened, so **no template, no proactive send, no H-05, and no schema change** is needed.

This is the owner's "safe December pilot" ask (13:07Z addendum, item 3). It is a **throw-away bridge**: WA-02..WA-06 replace every part of it, and its removal is part of WA-05ʰ's acceptance.

**Owner agent:** web-feature-engineer (handler) · tenant-security-warden (review) · **human author** for the route and the send call (public attack surface + a reply path beside the outbox). **Effort:** S–M. **humanPR:** **yes** (WA-00ʰ). **Earliest session:** ≥ 7.12, inside the AU+WA allowance (≤ 3 in December).

## 1. What it is (and is not)

| In | Out (refused with a fixed Hebrew line + web link) |
|---|---|
| Text from an **allow-listed owner phone** only | Every other sender: no reply at all (no enumeration) |
| "בוקר" / "סיכום" → today's brief as text (₪ waiting for approval, blocking gaps, top leak supplier) | Buttons that change anything, staged actions, undo (WA-07) |
| Free-text leak/approval questions → the existing Ask engine (`runAsk`, owner role, read-only tools, offline intents first) | Photos, documents, voice ("שלח באפליקציה" + link); the ingest path stays e-mail/web |
| "עצור" → pilot off for that phone (env flag flip by a human within 1 business day; immediate soft-mute in the handler) | Staff, chef, receiver, bookkeeper, suppliers, groups |
| A deep link to the screen after every answer | Proactive messages of any kind (07:30 push waits for WA-06ʰ/H-05) |

## 2. How it is wired (no new table, no outbox change)
- **Route:** new `apps/web/app/api/whatsapp/pilot/route.ts` (human-authored). Order: Meta `X-Hub-Signature-256` HMAC on the raw body (constant-time) → size cap 64 KB → JSON parse → ignore `statuses` → `wamid` dedupe (in-memory LRU per instance + Ask's per-restaurant burst limit; double replies are harmless because every reply is read-only).
- **Binding:** env `WA_PILOT_BINDINGS` = list of `{ phoneSha256, userId, restaurantId }`, set by a human in Vercel. Role is **always** `owner` and is re-read from `memberships` on every message (a removed owner loses access at once). No phone number in the repo or logs (hash only). If G-03 `users.phone_verified_at` is on `main`, also require it to be non-null.
- **Brain:** a server caller with `ctx.session = { userId, restaurantId, role }` from the binding, calling the existing read procedures under `withRestaurant` (RLS): `approvals.queueSummary`, `owner.leakHero`, `owner.leakGrouped`, `recovery.list`, and `ask.ask` for free text. No new tool, no new procedure. The Ask budget (`ask/budget.ts`, 60/day per restaurant) applies unchanged.
- **Mouth:** a single `sendReply(to, text)` that posts **one free-form text message** to the Cloud API, **only** while the last inbound from that phone is < 24 h old (checked from the webhook payload timestamp). It never sends a template, never sends to a non-allow-listed number, and is deleted when WA-06ʰ lands (design §D.5). This is the one deliberate exception to "everything through the outbox", and the reason this package is a human PR.
- **Logging:** no message text stored by us. Structured log line per message: `wamid`, restaurantId, intent, tool names, tokens, latency, ok/refused. Meta keeps its own copy (WD9 decides Meta's storage mode later).
- **Kill switch:** `WA_PILOT_ENABLED=0` (route returns 200 and does nothing) + removing the webhook in the Meta app. Both tested.

## 3. Preconditions (all human, WA-12ʰ step 1)
1. Meta app + WhatsApp Business Account + a dedicated number (never a personal phone), two-step PIN, display name "RestoMatch". Business Verification may still be pending; user-initiated replies to two people do not need the higher tiers (to confirm in the Meta console, UNVERIFIED here).
2. A payment method on the account is **not** required while total service replies stay under 1,000 a month for the number (Oct 2026 rule; design §E). Add one anyway with a low balance alert.
3. Written opt-in from each pilot owner with the AI-disclosure line (design §C.6), and a lawyer's OK on the notice (can be the short form).
4. The secrets (app secret, access token, verify token) are entered by the owner in Vercel. **No agent sees or requests them.**

## 4. Acceptance
- [ ] 30 golden owner conversations from WA-01's set (subset "pilot-owner") pass in the simulator on lab data, incl. 10 adversarial (injection in a supplier name, "approve everything", "show me another restaurant", "what's the weather", "send the supplier a message").
- [ ] Off-domain questions get the fixed line "אני עונה רק על נושאי הספקים, החשבוניות והדליפות של המסעדה שלך" (design §A.3), never a general answer.
- [ ] A non-allow-listed sender gets nothing; a removed owner gets nothing on the next message.
- [ ] Every ₪ in a reply comes from a tool figure (grounding) and is formatted by the server.
- [ ] No reply is sent outside 24 h of the owner's last message (unit test on the timestamp gate).
- [ ] Off states: env flag off → no send; Ask budget exhausted → offline canned answer.
- [ ] Removal plan written into WA-05ʰ's acceptance.
