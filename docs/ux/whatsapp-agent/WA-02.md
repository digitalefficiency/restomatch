# WA-02 · The agent core (brain), read-only: Ask's engine, per-role tools, ₪ redacted before the model
**One line:** a free-text WhatsApp message from a bound person becomes a short, grounded Hebrew answer from that person's own role tools, with ₪ formatted by the server and stripped for roles that may not see it, and a deep link appended after grounding. Button taps, commands and media never reach the model. Nothing is written: proposals are WA-07's.

- `runAsk` (`ask/index.ts:42`) already does reserve-before-spend, a tool loop (`MAX_TURNS = 4`, `ask/claude.ts:19`), grounding and an offline fallback, but only for **owner/manager** (`routers/ask.ts:12,23`, `managerProcedure`) and only over **4 leak tools** (`ask/tools.ts:27`);
- offline answers are `facts` for the web, not text (`ask/offline.ts:18-33`);
- screen links are relative and the grounding check strips absolute URLs (`ask/grounding.ts:223`);

## 4. What to build
- **Deterministic router** (`router.ts`): input = parsed message + binding. `interactive`/`button` → WA-07's token handler (stub now: "הפעולה תהיה זמינה בקרוב"); `image`/`document` → hand to ingest (WA-05ʰ); commands `עצור` · `אדם` · `עזרה` · `החלף מסעדה` · `החלף תפקיד` → fixed handlers (`עצור`/`החלף` call WA-04's identity API; stub until it exists); free text → `runAgent`.
- **Role tool registry** (`registry.ts`): `{ name, role[], procedure, inputSchema, redaction: 'none'|'chef'|'receiver', kind: 'read'|'proposal' }`. The model sees only its role's read tools (design §C.2 table). A test fails if a tool is reachable from a role not listed.
- **Server caller** (`caller.ts`): `appRouter.createCaller({ db, session: { userId, restaurantId, role } })` from the binding; never from model output.
- **Redaction** (`redact.ts`): runs on every tool result before the model, the renderer or a link builder. Receiver profile deletes every key matching `/ils|agorot|amount|total|price|cost|vat|leak|delta/i` recursively; chef profile allows ₪ only for `orders.*` and (later) recipe tools. Also applies G-07 `can('money.view')`.
- **`runAgent`** (`index.ts`): `runAsk` with `channel: 'whatsapp'`, the role's tools, the WhatsApp system prompt (`prompt.ts`: role, restaurant display name, today, closed intent list, refusal copy, "never write ₪ or links"; **no tenant data, thresholds or secrets**), ≤4 tool turns, prompt caching on the static prefix, the last 6 turns + `flow_state` as context (from `wa_conversations`, interim in-memory).
- **Hebrew renderer** (`render.ts`): turns grounded answers and offline `facts` into ≤1,024-char Hebrew text; every ₪ via `moneyText`; numbers he-IL; bidi isolation.
- **Links** (`links.ts`): absolute `https://<app>/dashboard/go?r=<rid>&to=…` (W2-04 go-links) appended **after** grounding.
- **Budgets** (`budget.ts`): per person 30 model turns/day inside the restaurant's 60/day and ≈$3/day; one in-flight model task per conversation; on exhaustion → model-off mode (canned intents + buttons).
- **Out of scope:** writes (WA-07), templates and sends (WA-06ʰ), identity (WA-04), the webhook (WA-05ʰ).
- **Owner decisions applied:**
  - the receiver gets no ₪ (redaction profile, before the model);
  - the chef gets ₪ only from order (and later recipe) tools;
  - the model proposes, the server decides: no write tool exists in this package;
  - MISSING_ON_INVOICE is never claimable (`lib/claims.ts:22` `NEVER_CLAIMABLE_TYPES`) and outside every leak figure (`LEAK_FILTER`, `packages/charts/src/leak-views.ts:134`, after #211 lands; until then the renderer must not present it as leak);
  - no "ask me anything": closed intents and a fixed refusal (design §A.3);
  - WD8: small tier optional, top tier for complex requests, 30 turns/person/day.

## 5. Acceptance criteria
1. **Taps, commands and media never call the model** (test: a stubbed model client records 0 calls for 20 such inputs).
2. **Closed intents.** Off-list text ("מה מזג האוויר", "תכתוב לי שיר") gets the fixed reply "אני עוזר רק בענייני חשבוניות, הזמנות, משלוחים ותביעות של {מסעדה}. לכל השאר: האפליקציה או \"אדם\"." and **no tool call**.
3. **Role tools only.** For each role the model's tool list equals design §C.2's read column; a forged tool name from the model is refused and logged `refusal: tool_not_allowed`.
4. **Redaction before the model.** For a receiver binding, the JSON passed to the model and to the renderer contains no key matching the receiver regex and no `₪` (test on `todayExpectations`, `orders.get`, `receiving.getPo`). For a chef binding, `owner.leakHero`, `approvals.*`, `recovery.*` are not callable, and `orders.get` keeps ₪.
5. **The model never writes ₪ or links.** Prose containing `₪`, a URL or a phone is sanitised (`sanitizeAnswer`) and flagged; all ₪ in the final text come from `moneyText` in the renderer; links are appended after grounding (test: an injected `https://evil.example` in a tool string never reaches the outbound text).
6. **Grounded or offline.** An answer whose figures do not match tool figures of the same unit is replaced by the renderer's facts text ("לפי הנתונים: …"), never sent ungrounded.
7. **Leak excludes MISSING_ON_INVOICE.** "כמה דלף אצל ירקות השרון?" on a seed with only MISSING_ON_INVOICE lines answers "אין דליפה פתוחה מול ירקות השרון החודש." with ₪0 not shown as a leak.
8. **Budgets.** The 31st model turn of a person in a day gets "הגעתם למכסת השאלות להיום. הכפתורים ממשיכים לעבוד." and model-off handling; another person in the same restaurant is unaffected until the restaurant budget is hit.
9. **Tenancy.** Every tool call runs under the binding's `restaurantId` with RLS; a question naming another restaurant's supplier returns "לא מצאתי ספק בשם הזה" (test with two tenants).
10. **Off switch.** With `whatsappAgent` off (interim: `aiAssistant` off) `runAgent` returns the fixed off reply and makes no model call.
