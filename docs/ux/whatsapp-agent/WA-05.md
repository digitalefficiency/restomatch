## 4. What to build
- **Guard order (same as intake, then agent steps):** (1) secret configured else 503; (2) per-IP 120/min; (3) size cap; (4) HMAC `X-Hub-Signature-256` over raw bytes else 401; (5) parse else 400; (6) `wamid` dedupe (unique in `wa_messages`) → 200 no-op; (7) replay: older than 7 days → 200 no-op; (8) `phone_number_id` must equal the shared RestoMatch number's id; (9) resolve sender via `app.wa_resolve_sender(sha256(E.164))`; (10) per-sender limit 20/min and 300/day.
- **Parser extension:** `interactive.button_reply{id,title}`, `interactive.list_reply{id,title}`, `button{payload,text}` (template quick reply), `statuses[]{id,status,timestamp,errors[]}`, `system{type,…}` (number-changed), plus `audio` parsed to `kind:'voice'` and answered "הודעות קוליות עוד לא נתמכות. כתבו או צלמו." (default: no voice in v1). Ops fields `template_category_update`, `phone_number_quality_update` are parsed and forwarded to WA-06ʰ/WA-11 alerts.
- **Routing:** statuses → `wa_messages.status` + outbox row write-back (WA-06ʰ API); unknown or ambiguous sender → one fixed reply, no model ("המספר הזה משמש את צוותי המסעדות שעובדות עם RestoMatch. לעניין הזמנה או חשבונית, פנו ישירות למסעדה."), at most once per number per 24 h; `חיבור RM-…` from an unbound sender → WA-04 `bind.ts`; bound + media → download now, ✅ reaction + typing indicator, `processInboundMessage` with the **binding's** restaurant (allow-list and OCR logic single-sourced); bound + tap → WA-07; bound + text → WA-02 router; update `wa_conversations.last_inbound_at`.
- **Hand-offs (one function each, no logic duplicated here):**
  - statuses → WA-06ʰ `recordWaStatus(wamid, status, errorCode)`;
  - `חיבור RM-…` → WA-04 `bindFromCode(sender, code)`;
  - taps → WA-07 `confirm(binding, buttonId, wamid)`;
  - text and commands → WA-02 `route(binding, message)`;
  - media → `processInboundMessage(db, channelForBinding, message, provider)`;
  - ops fields → WA-11 `alerts.record(kind, payload)`.
- **Owner decisions applied:**
  - nothing is ever sent to a supplier from this route; a supplier writing in gets one fixed reply;
  - WD1: one shared number; default: no voice notes in v1;
  - documents and captions are data, never instructions (they reach the model only as delimited fields, if at all).
- **Respond 200 fast:** heavy work (model, OCR) is enqueued; the handler returns within Meta's timeout; failures never return 5xx for a valid signed payload (Meta retries create duplicates).

## 5. Acceptance criteria
1. **Unsigned or wrong-signed → 401**; oversized → 413; malformed → 400; no secret → 503 (attack tests mirror `ingest.attack.test.ts:244`).
2. **The tenant never comes from the URL or payload:** a forged `restaurant_id`/`user_id` field in the body changes nothing (test).
3. **Supplier and unknown numbers never reach the model or a staff tool:** fixed reply, 0 model calls, 0 tool calls, ≤1 reply per number per 24 h.
4. **Duplicates:** the same `wamid` delivered twice → one routed event; the same tap delivered twice → one WA-07 commit (with WA-07's idempotency).
5. **Statuses recorded:** `delivered`/`read`/`failed` (with error code, e.g. 131048, 368) update `wa_messages` and the outbox row; never mark `sent` for a mock.
6. **Media single-sourced:** a bound manager's invoice photo lands in `processInboundMessage` with the binding's restaurant and is OCR'd only under the existing allow-list rules; the intake route and its tests are unchanged.
7. **Per-sender limits:** the 21st message in a minute gets one "רגע, יותר מדי הודעות. נסו שוב בעוד דקה." and nothing is processed.
8. **Kill-switch level 1:** with `FEATURES_OFF` including `whatsappAgent`, every bound text gets the fixed off reply ("השירות בוואטסאפ מושהה כרגע. הכל זמין באפליקציה.") and nothing else runs; statuses are still recorded.
9. **Number-changed system event** revokes the binding (WA-04) and sends nothing to the old chat.
10. **Public path:** `/api/whatsapp/agent` is in `publicPaths.ts`; no other public path is added.
